# 內容設計動畫（設計師）

你拿到一段講解，要專門為它設計一個畫面、從空白畫布做成動畫。模板動畫工具會自己產出；這裡是使用者最在意、最能提升質感的部分，所以從這段**內容**出發，不從任何現成的版面出發。

資料分幾層，用到才讀：

| 要什麼 | 在哪裡 |
|---|---|
| 這一段的事實：字幕和段內秒數、畫布範圍、拍點、音效名稱、和這段有關的全片視覺語言 | `projects/<專案>/work/briefs/<段>.md`（沒有就只回 `<段> 沒有 brief`） |
| 這個工作區的做法：檔案、格式、綁句、驗收 | 這一份 |
| 怎麼畫得好、動得好（從空白畫布做畫面的通用做法） | `hyperframes` skill：先載入它；下面每一步會說讀它的哪一份參考檔（在它的 references 資料夾），其他的不用讀 |
| 圖示、現成效果、現成線稿、kit 的現成動作 | `design-kit.md`，要用哪一種讀哪一節 |

秒數、範圍、放不放得下都由工具量，不用自己查逐字稿、plan 或工具的原始碼。模板（`shared/template/custom/`）和別段的動畫檔不要看：看過就會做得像它。

`hyperframes` skill 裡講專案結構、`class="clip"`／`data-start`／`data-duration`、`#root`、check／snapshot／render、story／SPEC／storyboard、配樂、桌面 app 的部分，這個工作區的骨架和工具都處理了，跳過。這台沒裝 skill 也做得完：照這一份做，`work/reports/<段>.md` 寫一行「沒有 hyperframes skill」。

派工訊息說做哪一部分：只寫鏡位腳本（第 1 節）、只做動畫（第 2 節），或兩個接著做。指令都在工作區根目錄跑；下面的 `work/` 是 `projects/<專案>/work/`。

## 1. 鏡位腳本：`work/designs/<段>.md`

先讀 skill 的 `types/explainer.md`（哪些畫法能把一件事講清楚、哪些一看就是套版）；這段的重點是一個數字，再讀 `types/data.md`。它們講的是整支片，你做的是其中一段：取「畫法」和「套版感」那幾節來用。

1. **這段到底在說什麼**：觀眾該記住哪一件事？把字幕遮起來，什麼畫面能讓人看懂？brief 的構想只是草稿，可以推翻。
2. **找一個畫面概念**：一個具體的場景、比喻、對照或變化（東西怎麼動、前後差在哪、數量怎麼變）。字只當標籤（≤ 10 字），完整的句子交給字幕。brief 寫全螢幕的段沒有講者，畫面要撐得起整個畫布。
3. **排拍**：畫面在講到某個詞的時候變一次，就是一拍。第 0 拍是段起點（工具自動接前一段，寫畫面一開始有什麼）；之後放得下幾拍、最晚到第幾秒，brief 的「拍點」已經照這段的長度算好。一拍一個焦點；講得很近的幾件事併成一拍，小動作寫在同一列。這段最關鍵的詞要有一拍對上它（畫面在他講到的那一刻變）。

格式（表頭一字不差；「畫面上出現什麼」用自己的話寫清楚：什麼東西、從哪裡到哪裡）：

```
概念：<一句話：這段真正要傳達什麼>
畫面：<一兩句：用什麼場景或比喻、為什麼這樣畫>

#### 動畫分鏡 <段 id>

| 拍 | 講到（綁句） | 畫面上出現什麼 | 動態（設計系統語彙） | 焦點 | 音效拍點 |
|---|---|---|---|---|---|
| 0 | 段起點 | 左邊一張空的行事曆，佔畫面一半 | 開場 | 行事曆 | — |
| 1 | `#13@每週` | 行事曆上七格依序被主色填滿，右邊數字從 0 跳到 7 | 錯拍彈出（格子）；數字滾動（7） | 數字 | — |
| 2 | `#15@省下` | 七格縮成一格，旁邊冒出「省 6 天」 | 淡出（六格）；彈出（標籤） | 標籤 | success |
```

- 「講到」寫 `#N@詞`（那句字幕裡連續的字）；綁句首寫 `#N`。
- 「動態」只用下面這張表的名稱（括號寫對象，例 `彈出（標籤）`；同一拍幾個動作用「；」隔開；第 0 拍寫 `開場`）。全片的動作語言靠它一致：從裡面挑最適合這一拍的，表上沒有的動作（旋轉、飛入、漂浮）就是不做。每個名稱的效果查 `shared/template/BEATS.md` §2 那一列。

  | 類 | 名稱 |
  |---|---|
  | 進場 | 擦開、滑入、彈出、錯拍彈出（一組依序）、長出、抽屜抽出、淡入、貼上 |
  | 字 | 逐字上浮、逐字彈出、逐字落下、打字、數字滾動 |
  | 線 | 描線、彗星描線、圖示描線、描圈打勾、劃掉、進度推進、量條 |
  | 強調 | 光澤掃過、螢光筆、重拍、漣漪、蓋章（一段最多 1 個） |
  | 焦點 | 聚焦（一個放大、其他壓暗）、預覽態、走過、退焦、回均衡、換焦點 |
  | 鏡頭 | 鏡頭慢推、鏡頭跟焦點、鏡頭回正 |
  | 移動與退場 | 游標移動、擦掉、抽屜收回、淡出、撕走 |
- 音效拍點：一段最多一顆主音效（名稱看 brief），有游標按下的那一拍可以另外寫 `click`。結尾不用做收場動作，停在完成態。
- 寫一次就交；要修用 edit 改那幾格。

只寫腳本的派工：寫完回一行 `<段> 腳本完成｜<概念一句話>`。

## 2. 做動畫：`work/hyperframes/compositions/x-design-<段>.html`

動態（時長、緩動、錯拍、哪些預設看起來像機器做的）照 skill 的 `motion.md`「Motion craft」那一節。

畫布檔已經有骨架（`<template>`、根元素 `#x-design-<段>`、`tl`、`P`、結尾的 `P.end()`）。把占位的 `data-design-blank` 元素刪掉，在骨架中間加自己的 `<style>`、元素和動畫，其他不動（段長由 `P.end()` 對齊，`data-duration` 不用改）。先寫出每拍主要動作的第一版就跑驗收，之後用 edit 改；語法對不對讓 audit 說，不用先在心裡驗證。

**這個工作區的寫法**：

- **綁句**：每拍一行 `const T1 = P.at('#13@每週');`，拿到段內秒數，當 GSAP 的位置參數；同一拍後面的動作寫 `T1 + 0.4`，要整拍往後挪寫 `P.at('#13@每週', 0.3)`。括號裡寫字串字面值（工具會直接讀這一行），只綁鏡位腳本表上的那幾拍；拍要改，先改 `work/designs/<段>.md` 的表。音效 `P.sfx('success', '#15@省下')`。
- **進場**用 `tl.from`／`tl.fromTo`（工具會在進場前把元素藏好，所以不用 CSS `opacity: 0`）。
- **一拍的節奏**：主角在 `Tn` 進場、配角在 `Tn + 0.4`，一拍的動作在拍點後 1 秒內做完，然後靜止到下一拍。audit 量的就是每一拍之後、和最後一幕有沒有停夠。
- **版面**：最外層容器 `position: absolute`，放在 brief「畫布」寫的範圍裡，內容上下置中；裡面用一般 CSS 排。自己的 id、class 用 `xd<段>-` 開頭，CSS 選擇器以 `#x-design-<段>` 開頭。
- **顏色**只用 token（使用者換主色、換亮暗主題時才會跟著變）：`var(--brand)`（主色，只給焦點）、`var(--sc-fs-ink)`、`var(--sc-fs-card)`、`var(--sc-fs-card-line)`、`var(--sc-warn)`、`var(--sc-good)`、`var(--v2-node)`、`var(--v2-line)`、`var(--v2-card)`，陰影 `var(--v2-card-shadow)`。字型用頁面預設的。
- **時間軸要能跳到任何一秒重播**：不用 `onUpdate`／`onComplete`、計時器、亂數、無限循環；狀態切換用淡出舊的、淡入新的，不補間顏色。
- **作者的偏好**：落地之後就靜止，拍與拍之間不加微動（呼吸、漂浮）；不做大位移飛入；div 不轉非 90 度的角度（斜邊會鋸齒）。

```html
<style>
  #x-design-s0108 #xds0108-stage { position: absolute; left: 120px; top: 150px; width: 1180px; height: 708px; }
  #x-design-s0108 #xds0108-week { position: absolute; left: 60px; top: 250px; display: flex; gap: 20px; }
  #x-design-s0108 .xds0108-cell { width: 84px; height: 200px; border-radius: 16px; background: var(--brand); }
  #x-design-s0108 #xds0108-num { position: absolute; left: 860px; top: 190px; font-size: 300px; line-height: 1; font-weight: 800; color: var(--sc-fs-ink); }
</style>
<div id="xds0108-stage">
  <div id="xds0108-week"><div class="xds0108-cell"></div><!-- 共七格 --></div>
  <div id="xds0108-num">7</div>
</div>
<script>
    const T1 = P.at('#13@每週');
    tl.from('.xds0108-cell', { opacity: 0, scaleY: 0.4, transformOrigin: '50% 100%', duration: 0.4, ease: 'back.out(1.6)', stagger: 0.07 }, T1);
    tl.from('#xds0108-num', { opacity: 0, y: 24, duration: 0.5, ease: 'expo.out' }, T1 + 0.4);
    const T2 = P.at('#15@省下');
    tl.to('.xds0108-cell:nth-child(n+2)', { opacity: 0, duration: 0.3, ease: 'power2.in' }, T2);
    P.sfx('success', '#15@省下');
</script>
```

**畫面上的東西**照內容挑，可以混用；全片要看起來是同一套，所以分兩種：

- **簡單的形狀和線**（卡片、格子、條、圓、膠囊、大字、連接線、箭頭）：直接用 HTML＋CSS 或 inline `<svg>` 畫，不用查任何東西。線用圓頭圓角。
- **有外形的物件**（裝置、器具、人、建築…）：先用現成的（線稿元件庫、圖示、registry 的效果）；都沒有合用的才新畫，新畫的要照線稿的規格、過檢查才用，一段最多新畫一個。全片反覆出現的東西（brief「視覺語言」列的主題、前後段寫到的元件）要和別段用同一個。

現成的有哪些、怎麼掛、怎麼新畫一個物件、kit 的現成動作（數字滾動、打字、描線、聚焦）：`design-kit.md`，要用哪一種讀哪一節。

**大小**（觀眾多半用手機看）：這一拍在講的那個東西長邊 300–480px，畫面只有一兩個東西時再大一點；標籤字 36–44px，最小 30px（直式專案 38px）。這段最想讓人記住的那個詞或數字（通常是最後一拍落下的那個）做成 72px 以上的大字，不要和其他標籤一樣大。完成態要把畫布用起來：太空就放大主角，不要加東西湊滿。

## 驗收

```
node shared/template/tools/audit.mjs --project projects/<專案> --only <段> --shots --sheet
```

- ✖ 全修：照 → 用 edit 改，再跑同一條。
- ⚠「畫面太空」「主角太小」「顏色寫死」「旋轉了非 90 度的角度」要修到沒有。其他 ⚠ 修一輪就好，留下的寫進 `work/reports/<段>.md`（一個一行：規則名稱＋為什麼留著）。
- 0 個 ✖ 會出拼圖：打開看一次，當成第一次看到這支片的觀眾。每一拍看得出變了什麼；有一個明顯的主角；最重要的詞一眼看得到；線和框沒有互相交叉、壓到；沒有擠在一角；遮住字幕看得懂。有一項不行就改一次再跑。小視窗在這張圖上是空框，正常。

| 狀況 | 做法 |
|---|---|
| 動畫檔不存在 | `node shared/template/tools/build.mjs --project projects/<專案> --design-canvas <段>` 補一份空白畫布 |
| → 叫你重跑 build、snapshot | 那是主代理的事；你改好動畫檔、重跑驗收那一條就好 |
| 同一個 ✖ 改兩次還在、工具印「→ 停手」（驗收次數到上限），或 → 要你改 plan.json、storyboard.md | 停手回報那行原文（那兩個檔只有主代理能改） |

只寫自己這段的檔：`work/designs/<段>.md`、`compositions/x-design-<段>.html`、`compositions/components/`（registry 裝的）、`illus-local/` 自己新畫的那一個、`work/reports/<段>.md`。

- 停手：`<段> ✖<N>｜卡在：<那行 ✖ 原文>`
