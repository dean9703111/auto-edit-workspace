# 長片切直式短片

使用者說「從這支長片切短片」「把這集剪成幾支短影片」「切 Shorts」時照這份做。前提：長片專案已經剪乾淨（有 `work/rough.mp4`、`work/rough.srt`）。只會新增一個專案，不動長片專案的任何檔。

## 步驟

**1. 列候選**

```
node shared/template/tools/media.mjs shorts --project projects/<長片專案>
```

完成判準：印 `✓ 短片候選 N 段`，表在 `work/shorts.md`。印「找不到…的段落」就照它說的做，不要自己切。

**2. 評分**

讀 `work/shorts.md` 每一列的句號範圍，對照 `work/rough.srt` 把那一段的字幕讀完，再填「評分」（高／中／低）和「理由」（一句話）。照這個順序看，前面的不過關就是「低」，不用看後面：

| 順序 | 看什麼 | 過關的樣子 | 不過關的樣子 |
|---|---|---|---|
| 1 | 沒看過長片的人看得懂嗎 | 這一段自己把事情講完 | 開頭在講「剛剛那個」「前面提到的」、主詞是「它」；表上有 ⚠ 的特徵 |
| 2 | 第一句 | 一開口就是主張、問題、結果或數字 | 打招呼、鋪陳、「接下來我們來看」 |
| 3 | 有沒有一個重點 | 講完一個做法、一個比較或一個結論 | 講到一半、同時講好幾件事 |
| 4 | 最後一句 | 停在結論或好處上 | 在預告下一段、話沒講完 |

- 同一段話出現在好幾列（起點差幾句）時只留評分最高的一列。
- 「高」不到 3 列就照實列出來，不要為了湊數把「中」改成「高」。
- 不要改字幕、不要把不相連的句子拼成一段。

**3. 給使用者選**

把「高」的幾列（句號、時間、長度、第一句、理由）列給使用者，問要做哪幾段、各取什麼名稱。使用者沒回之前不要切。

**4. 切出來、開成新專案**（使用者選的每一段跑一次）

```
node shared/template/tools/media.mjs shorts --project projects/<長片專案> --pick "#12-#25" --name <新專案名稱>
```

完成判準：印 `✓ 短片專案：projects/<新專案名稱>`。把這一行原文貼給使用者；括號裡寫「會偏軟」時一起講，問他有沒有比較大的原檔。
接著請使用者看一眼 `projects/<新專案名稱>/assets/camera/` 那支影片，講者有沒有在畫面中間。

**5. 剪新專案**

使用者確認後，照一般流程剪新專案（版式是直式，工具會自己認）：`用 auto-edit-longform 剪 projects/<新專案名稱>`。短片不到三分鐘，不用章節轉場；第一段畫面要在第一句就出現。

## 回報

候選幾段、高／中／低各幾段、建議做的那幾列；最後一行：`→ 下一步：說要做哪幾段和名稱（例：第 3 段叫 EP1-short1）`。

## 退路

| 症狀（工具原文） | 做法 |
|---|---|
| `✖ 這個專案還沒有 work/rough.mp4 和 work/rough.srt` | 先對長片專案「剪乾淨」 |
| `✖ projects/<名稱> 已經有了` | 請使用者換一個名稱，不要刪舊的 |
| `✖ 字幕裡找不到 #N 到 #M 這一段` | 句號照 `work/shorts.md` 的表重抄 |
| 講者不在裁出來的畫面中間 | 長片專案的 plan.json 還沒有 `speakerBox`（工具取畫面中間）：先對長片專案跑 `node shared/template/tools/qc.mjs speaker --project projects/<長片專案> --write`，刪掉新專案前先問使用者，再重切 |
