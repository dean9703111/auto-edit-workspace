# 分章寫分鏡：子代理的派工與做法（兩回合）

`build.mjs --scaffold` 會把影片切成幾份（有 `##` 章節照章節切，一份太長再切、太小的份併起來）。**一份派一個子代理，同一則回覆一次全部派出**（一次最多 4 個，超過就分批）。只有 1 份或沒有子代理工具，主代理自己照這份做。

分兩回合，中間由主代理看全片：

| 回合 | 做什麼 | 讀什麼 | 寫什麼 |
|---|---|---|---|
| 第一回合 | 語意地圖：句子分組、標語意和分級（A 亮點、B 結構、C 串場） | `語意.md`、自己那份 `chNN.md` | `work/drafts/<chNN>.map.md` |
| （主代理） | 全片校正：挑 A、統一標法、寫視覺語言（`references/director.md`） | 合併後的 `語意地圖.md` | 各份地圖、`視覺語言.md` |
| 第二回合 | 照地圖寫草稿：大綱 → 骨架 → 填字 | `共用.md`、自己那份 `chNN.md`、校正後的地圖、`視覺語言.md` | `work/drafts/<chNN>.outline.md`、`<chNN>.json` |

## 派工訊息（工具會印出來，照抄）

```
你只負責 projects/<專案> 的分鏡 <chNN> 這一份（全片 N 份：…，其他份有別的子代理，不要碰）第一回合：語意地圖。照 .agents/skills/auto-edit-storyboard/references/chapter-worker.md 做。
你只負責 projects/<專案> 的分鏡 <chNN> 這一份（全片 N 份：…，其他份有別的子代理，不要碰）第二回合：照語意地圖寫草稿。照 .agents/skills/auto-edit-storyboard/references/chapter-worker.md 做。
```

括號裡是全片有哪幾份，不是你的工作：只讀寫自己那份（`<chNN>.*`）的檔，看到別份的檔比你預期的新或內容不一樣，不要覆蓋，回報主代理。

主代理能接續子代理（例如 SendMessage）就請第一回合那個子代理接著做第二回合，不用重讀字幕；不能接續就重派第二回合，照下面做一樣做得完。

指令都在工作區根目錄跑；下面的 `P` 是 `projects/<專案>`。不要讀 `shared/template/tools/`、`kit/*.js`、其他份的字幕。`<chNN>.md` 第一段沒有提到 `--map` 就是舊版：停下來回報主代理重跑 `--scaffold`。

## 第一回合：語意地圖

1. 讀 `P/work/分鏡素材/語意.md` 和自己那份 `P/work/分鏡素材/<chNN>.md`。**這一回合不讀 `共用.md`、`寫法.md`，不挑模板、不想畫面細節**。
2. 寫 `P/work/drafts/<chNN>.map.md`，一組句子一行：`句號範圍 | 語意 | 級 | 在講什麼 | 特徵或 A 的理由`（格式、語意清單、分級看 `語意.md`）。連續講同一件事的幾句併成一行；A 只是提名，寫一句理由，不用湊數（`<chNN>.md` 開頭寫了這一份大約幾段）。派工訊息說這次不標候選（快速初稿）時，一律不寫 A。
3. 驗：`node shared/template/tools/build.mjs --project P --map <chNN>`。✖ 全修。⚠ 只修一輪：照 → 用 Edit 改那幾行，再跑同一條一次就停。印「地圖通過」就交件。
4. 回報一行（格式見最後），等主代理。

## 第二回合：照地圖寫草稿

先寫大綱（段落和模板，工具馬上檢查放不放得下），再填畫面上的字。欄位、起訖、anchor 工具會寫好。

1. 讀 `P/work/分鏡素材/共用.md`（第 3 節的對照表不用讀：每一行能用的模板下一步工具會印）、自己那份 `<chNN>.md`，有 `P/work/分鏡素材/視覺語言.md` 也要讀（`寫法.md` 到第 4 步才查）。接續第一回合的子代理不用重讀 `<chNN>.md`。
2. 跑 `node shared/template/tools/build.mjs --project P --map <chNN>`：印出主代理校正後的地圖每一行的秒數和放得下的模板（照語意縮好的），放不下的另列最短秒數。每個模板後面括號裡是「什麼句子用它」（有的還寫一集最多幾次）：**照那句話挑最像這一行的，不是挑第一個**；括號不要抄進大綱。**挑放得下的**，太短的行和前後一行併成一段；**地圖的級不要改**（A 名單是全片定的），覺得不對寫進 `decide`。`視覺語言.md` 和工具的檢查（相鄰兩段不同模板、時間下限）衝突時，照工具。
3. **寫大綱** `P/work/drafts/<chNN>.outline.md`，一段一行：`id | from | to | 模板 | 在講什麼 | 候選構想`。照地圖一行寫一段（太長可以拆兩段）；模板從 `--map` 印的那幾個裡挑。**這一步不讀 `寫法.md`、不跑 `--spec`**，不估秒數、不排拍點：放不放得下、拍綁哪幾句，`--outline` 會一段一段印出來。
   - A 的行：照樣先填一個模板，候選構想寫一句話（畫面上發生什麼事）；B、C 的行候選構想寫 `—`。
   - C 的行：用最便宜的（字卡動態、12 關鍵詞），或併進前後那一段。
   - 有對得上的素材用 `media`；`to` 寫下一段的 `from`（段與段之間的空檔工具會自動接上）；相鄰兩段不要同一個模板。`<chNN>.md` 的「章節段」不寫進大綱（第 4 步再貼）。例：
   ```
   s0101 | #1 | #2e | key-point | 這一章要做什麼 | —
   x0102 | #3 | #8e | x-scene | 錄完跑去手機旁確認 | 人在手機和電腦之間來回跑，腳印越來越多
   ```
   跑 `node shared/template/tools/build.mjs --project P --outline <chNN>`。印「未通過」就照 ✖ 改大綱再跑；⚠ 改一輪就好，印出「草稿骨架：…」就往下填，留下的 ⚠ 到 `--check-draft` 再看。之後再改大綱重跑，填過的段會留著，貼進去的章節段會被洗掉，要重貼。
4. **填骨架**：先 Read 一次整份 `<chNN>.json`，把所有 `<…>`（畫面上的字，`<>` 裡是字數上限）、`#N@詞`（講到那個東西的詞，要是那句字幕裡連續的字）、`designWhy` 填好，用 Write 一次寫回（`auto` 格和其他欄位原樣保留）。`<chNN>.md` 有「章節段」就原樣貼進 `segments`（位置照它寫的）。清單、條列（fs-list、title-list、side-panel、steps…）每一項把最該記住的詞包成 `**詞**`（主色；每項最多 1 個，例 `**Node.js** 跑動畫的環境`）。金句寫 `quotes`，每份最多 2 則，挑最像翻轉句的；拿不定寫 `decide`。**情緒點寫 `moods`**（音效照它放，不照模板）：`<chNN>.md` 的「情緒點」寫了這一份要幾個、列了關鍵詞對到的句子；挑講者情緒最強的那個詞，寫 `{ "at": "#N@詞", "kind": "pain" }`（`pain` 痛點、`win` 解法、`turn` 反轉、`land` 落定、`quote` 金句），最強的那一下（金句、反轉、數字落定）加 `"zoom": true`（講者畫面爆衝推近，`<chNN>.md` 寫了最多幾次）。音效名稱、秒數、上限工具處理。時間寫 `auto` 的格子不用動：卡上的字用字幕原詞，`--check-draft` 會找到講到它的地方補成 `#N@詞`；卡上的字是改寫的（字幕沒有這幾個字）就直接寫 `#N@詞`。`why` 工具先寫了模板的用途，要改再改。圖示寫中文常見的（手機、電腦…）工具會換成英文。要查的寫檔前一次查完：
   - 模板欄位：`node shared/template/tools/build.mjs --project P --spec "x-scene,fs-flow"`
   - 圖示名稱：`node shared/template/tools/build.mjs --project P --icons 手機,雲端`
   - 這幾句逐字稿聽成什麼（挑 `@詞`）：`node shared/template/tools/build.mjs --project P --words 28-41`
5. 驗這一份：`node shared/template/tools/build.mjs --project P --check-draft <chNN>`。從這裡起只用 Edit 改它點名的那幾格，不要再整份 Write。✖ 全修（`auto` 對不到的格子，工具會說要落在哪兩格之間）。⚠ 只修一輪：照 → 用 Edit 改那幾格（不要整份重寫），再跑同一條檢查一次就停，留下的 ⚠ 寫進 `decide` 或回報。印「通過」或「可以交件」都算過關。同一個 ✖ 改 2 次還在，停下來回報指令和 ✖ 原文。

## 交給工具，不用先想

這些 `--map`、`--outline`、`--check-draft` 都會用實際資料檢查，錯了會直接說改哪裡：地圖接不接得起來、語意名稱、秒數、模板的時間下限（拍距、段長）、字數上限、圖示名稱、id 重複、段與段接不接得起來、相鄰同模板、候選和地圖上的 A 對不對得上；`auto` 的時間也由工具對字幕找。**每一步寫完就跑檢查**，不要在心裡先算時間或反覆確認規則；拿不定的寫進 `decide` 繼續往下寫。要查的寫檔前一次查完（`--spec a,b`、`--icons 甲,乙`），不要一個一個查。

## 不要做

- 不要查 `transcript.json`、不要自己算秒數：寫 `#N@詞`（字幕原文裡的 2–4 個字），工具算。
- 不要寫 script、不要讀別份的字幕，也不要讀 `講稿.md`、`rough.srt`：這一份的字幕都在 `chNN.md`。字幕有錯字寫進 `decide`，不要自己改（主代理處理）。
- 不要寫 plan.json、storyboard.md、`語意地圖.md`、`視覺語言.md`，不要跑 `--map-merge`、`--merge-drafts`：主代理合併、校正，分鏡表由工具產生。
- 第二回合不要改地圖的級、不要在不是 A 的段寫候選構想。
- 金句只放 `quotes`，不要排成段。拿不定的事放 `decide`，不要停下來問。
- 有 `P/work/screen-sync.json`（邊錄邊講）時：字幕開始時間落在它某一段 `from`–`to`（秒）裡的句子不用寫進地圖、不用排畫面，那裡由 sync 段蓋（合併時工具會自己放進 plan.json）；`--map`、`--check-draft` 不會報那幾句。

工具呼叫：第一回合最多 6 次，第二回合最多 16 次（讀檔、地圖、大綱、骨架、填寫、檢查加起來）。

## 回報

只回一行，不要寫過程：

- 第一回合：`<chNN> 地圖 <N> 行｜A <N>、B <N>、C <N>｜✖0 ⚠<N>`
- 第二回合：`<chNN> <N> 段｜✖0 ⚠<N>｜內容設計候選 <N> 段｜情緒點 <N> 個`

拿不定的事放草稿的 `decide`，主代理會收齊。
