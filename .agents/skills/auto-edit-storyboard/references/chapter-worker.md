# 分章寫草稿：子代理的派工與做法

`build.mjs --scaffold` 會把影片切成幾份（有 `##` 章節照章節切，太長再切；沒有章節約每 5 分鐘一份）。**一份派一個子代理，同一則回覆一次全部派出**（一次最多 4 個，超過就分批）。只有 1 份或沒有子代理工具，主代理自己照這份做。

## 派工訊息（`--scaffold` 會印出來，照抄）

```
你負責 projects/<專案> 的分鏡草稿 <chNN>。照 .agents/skills/auto-edit-storyboard/references/chapter-worker.md 做。
```

## 做法

指令都在工作區根目錄跑；下面的 `P` 是 `projects/<專案>`。不要讀 `shared/template/tools/`、`kit/*.js`、其他章的字幕。

分兩步寫：先定段落和模板（工具馬上檢查放不放得下），再填畫面上的字。不要一次想完整份 JSON：欄位、起訖、anchor 工具會寫好。

1. 讀 `P/work/分鏡素材/共用.md`、自己那份 `P/work/分鏡素材/<chNN>.md`，有 `P/work/分鏡素材/視覺語言.md` 也要讀（`寫法.md` 到第 3 步才查）。`<chNN>.md` 第一段沒有提到 `--outline` 就是舊版：停下來回報主代理重跑 `--scaffold`。有 `視覺語言.md` 時，內容設計動畫候選只標它列給這一章的句號；`--outline`、`--check-draft` 印「內容設計動畫候選 N 段…約 M 段」的 ⚠ 不用補，在 `decide` 寫「候選照視覺語言.md」。派工訊息說這次不標候選時，大綱的候選構想全寫 `—`，同樣的 ⚠ 不用補，`decide` 寫「這次不標候選」。
2. **寫大綱** `P/work/drafts/<chNN>.outline.md`，一段一行：`id | from | to | 模板 | 在講什麼 | 候選構想`（不是候選寫 `—`）。只想段落和模板，模板從 `共用.md` 第 3 節的對照表挑；**這一步不讀 `寫法.md`、不跑 `--spec`**（欄位和時間下限是第 3 步的事），不估秒數、不排拍點：放不放得下、拍綁哪幾句，`--outline` 會一段一段印出來。`to` 寫下一段的 `from`；寫成「講到第幾句」也沒關係，段與段之間的空檔工具會自動接上。有對得上的素材用 `media`；**連續講同一件事的幾句併成一段**；每段都要有畫面（講者直講的地方也放字卡或動畫）；相鄰兩段不要同一個模板；約三成的段寫候選構想（一句話：畫面上發生什麼事），候選那段一樣先填一個模板，使用者在停點 ③ 勾了才換成內容設計動畫。`<chNN>.md` 的「章節段」不寫進大綱（第 3 步再貼）。例：
   ```
   s0101 | #1 | #2e | key-point | 這一章要做什麼 | —
   x0102 | #3 | #8e | x-scene | 錄完跑去手機旁確認 | 人在手機和電腦之間來回跑，腳印越來越多
   ```
   跑 `node shared/template/tools/build.mjs --project P --outline <chNN>`：段長、相鄰模板、接縫、候選數量工具都算好了。印「未通過」就照 ✖ 改大綱再跑；⚠ 改一輪就好，印出「草稿骨架：…」就往下填，留下的 ⚠ 到 `--check-draft` 再看。之後再改大綱重跑，填過的段會留著，貼進去的章節段會被洗掉，要重貼。
3. **填骨架**：先 Read 一次整份 `<chNN>.json`，把所有 `<…>`（畫面上的字，`<>` 裡是字數上限）、`#N@詞`（講到那個東西的詞，要是那句字幕裡連續的字）、`designWhy` 填好，用 Write 一次寫回（`auto` 格和其他欄位原樣保留）。`<chNN>.md` 有「章節段」就原樣貼進 `segments` 最前面。金句寫 `quotes`，每份最多 2 則，挑最像翻轉句的；拿不定寫 `decide`。時間寫 `auto` 的格子不用動：卡上的字用字幕原詞，`--check-draft` 會找到講到它的地方補成 `#N@詞`；卡上的字是改寫的（字幕沒有這幾個字）就直接寫 `#N@詞`。`why` 工具先寫了模板的用途，要改再改。圖示寫中文常見的（手機、電腦…）工具會換成英文。要查的寫檔前一次查完：
   - 模板欄位：`node shared/template/tools/build.mjs --project P --spec "x-scene,fs-flow"`
   - 圖示名稱：`node shared/template/tools/build.mjs --project P --icons 手機,雲端`
   - 這幾句逐字稿聽成什麼（挑 `@詞`）：`node shared/template/tools/build.mjs --project P --words 28-41`
4. 驗這一份：`node shared/template/tools/build.mjs --project P --check-draft <chNN>`。從這裡起只用 Edit 改它點名的那幾格，不要再整份 Write。✖ 全修（`auto` 對不到的格子，工具會說要落在哪兩格之間）。⚠ 只修一輪：照 → 用 Edit 改那幾格（不要整份重寫），再跑同一條檢查一次就停，留下的 ⚠ 寫進 `decide` 或回報。印「通過」或「可以交件」都算過關。同一個 ✖ 改 2 次還在，停下來回報指令和 ✖ 原文。

## 交給工具，不用先想

這些 `--outline`、`--check-draft` 都會用實際資料檢查，錯了會直接說改哪裡：秒數、模板的時間下限（拍距、段長）、字數上限、圖示名稱、id 重複、段與段接不接得起來、相鄰同模板、候選數量；`auto` 的時間也由工具對字幕找。**每一步寫完就跑檢查**，不要在心裡先算時間或反覆確認規則；拿不定的寫進 `decide` 繼續往下寫。要查的寫檔前一次查完（`--spec a,b`、`--icons 甲,乙`），不要一個一個查。

## 不要做

- 不要查 `transcript.json`、不要自己算秒數：寫 `#N@詞`（字幕原文裡的 2–4 個字），工具算。
- 不要寫 script、不要讀別章的字幕，也不要讀 `講稿.md`、`rough.srt`：這一份的字幕都在 `chNN.md`。字幕有錯字寫進 `decide`，不要自己改（主代理處理）。
- 不要寫 plan.json、storyboard.md：主代理合併，分鏡表由工具產生。
- 金句只放 `quotes`，不要排成段。拿不定的事放 `decide`，不要停下來問。
- 有 `P/work/screen-sync.json`（邊錄邊講）時：字幕開始時間落在它某一段 `from`–`to`（秒）裡的句子不用排畫面，那裡由 sync 段蓋（合併時工具會自己放進 plan.json）；`--check-draft` 不會報那幾段沒畫面。

每份最多 16 次工具呼叫（讀檔、大綱、骨架、填寫、檢查加起來）。

## 回報

只回一行：`<chNN> <N> 段｜✖0 ⚠<N>｜內容設計候選 <N> 段`。拿不定的事放草稿的 `decide`，主代理會收齊。不要寫過程。
