# 照修改單改（流程 F）

給 `auto-edit-review` 流程 F 用。使用者在剪輯台右側「修改單」選段、點標籤或寫描述，按「複製給 AI」：待改的段存到 `work/feedback/editor-requests.md`（EDITOR.md「修改單」），剪貼簿只放一行指令「照剪輯台修改單改這 N 段（<檔案路徑>）：…」。使用者貼上這行、說「照修改單改」或貼上開頭是「# 剪輯台修改單」的文字，就照這份做。

修改單就是使用者確認過的改法：**直接做**，不開 `versions.mjs new`、不寫分鏡提案、不停停點 ③。這仍是一輪回饋：`versions.mjs begin --seg <段,段> --say "照修改單改"` 開始，全部改完跑 `versions.mjs finish`。

## 1. 讀修改單

每段一節 `## k. <段 id>　<名稱>`：動畫是什麼、「檔案」（自訂動畫、錄影；從工作區根目錄寫起的路徑，照抄就能用）、完成影片時間、plan.json 起訖、「要改」（標籤）、「描述」（使用者原話）、「對應字幕」（`#N 文字`）。貼上的和檔案不一樣時以使用者貼上的為準。「plan.json 裡找不到這段」→ 那段不做，回報裡問使用者是哪一段。

## 2. 標籤怎麼解讀

描述和標籤衝突時照描述。

| 標籤 | 改法 |
|---|---|
| 流程更細節 | 步驟拆細、多幾站（一站一個動作），每站綁 `#N@詞`；站數照字幕講到的步驟，不自己編 |
| 以圖像展示為主 | 文字降到標題＋每站 ≤ 6 字標籤，主體換插圖、圖示或介面示意（`kit/illus-style.md`、`x-ui-mock`） |
| 文字少一點 | 刪說明句，只留關鍵詞；清單每條 ≤ 8 字 |
| 畫出關係（箭頭、引線） | 加連接線、箭頭或引線（BEATS.md §2 的名稱），讓前後、因果看得出來 |
| 換一種動畫 | 換情境或版型（BEATS.md 選另一種拍型）；資訊卡、字卡換成情境動畫 |
| 動作慢一點 | 拉長站與站的間隔、進場時間；不超過段長、不早於講到的詞 |
| 跟講的話對齊 | 每個出現時間綁 `#N@詞`，差 ≤ 0.5 秒（audit「綁句對不上」0 個） |
| 更有質感 | 加層次（底版、陰影、光暈）、鏡頭慢推、鏡頭跟焦點（BEATS.md §2 的名稱）；不加文字 |
| 標註更清楚（錄影） | `marks` 的框對準要看的地方（要文字說明用 `callouts`）；同時最多 2 個 |
| 推近到操作區（錄影） | 加 `moves` 推近到操作的位置 |
| 加步驟清單（錄影） | 橫式影片的直式錄影加 `side`；其他寫 `steps`（不和角標重複） |
| 換成動畫（錄影） | 改成不透明全幕情境動畫（介面操作用 `x-ui-mock`），錄影段移除或縮短 |
| 換一段錄影 | 照 `auto-edit-screen` 找 `assets/screen/` 裡對得上講解的另一支 |

## 3. 分工

| 這段要改的 | 誰做 |
|---|---|
| 模板動畫（`template`＋`slots`）的文字、條目、時間 | 你自己改 plan.json，不用派 |
| 字卡、資訊卡只改文字、條目、時間 | 你自己改 plan.json，不用派 |
| 字卡、資訊卡、模板動畫要換成別的模板 | 你改 plan.json 那段的 `template`／`scene`＋`slots`（寫法在 `work/分鏡素材/寫法.md`），不用派 |
| 「換一種動畫」「以圖像展示為主」要專門設計 | 你把那段改成 `"design": true`（拿掉 `template`、`slots`），派設計師（`.agents/skills/auto-edit-motion/references/design-build.md`）：修改單就是確認過的改法，不用停 ③ |
| 內容設計動畫的內容；`slots` 做不到的改動 | 一段一個子代理改那支檔，派工照 `.agents/skills/auto-edit-motion/references/worker-brief.md` |
| 錄影段的 `marks`、`moves`、`side`、`steps`、換成動畫 | 你自己改 plan.json；換一段錄影照 `auto-edit-screen` 的筆記挑 |

**同一則回覆一次全部派出**；派工訊息的「要改什麼」寫：

```
修改單（使用者確認過的改法，直接做，不用新分鏡）：
要改：<標籤>
描述：<使用者原話>
現在的動畫分鏡：照 work/storyboard.md 這段（grep -n -A30 "動畫分鏡 <段 id>" projects/<專案>/work/storyboard.md），照上面的改法改
```

收件、整合照 AGENTS.md「子代理分工」第 2 條。

## 4. 驗收與紀錄

- 全部回來後跑 `versions.mjs finish`（build、量、存改後版本、寫驗證、記停點 ④），打開它印的圖，只看改到的段。
- 寫 `work/feedback/r<N>.md`：「分類」每段一列（個案、改哪段、照哪個標籤或描述）；「改了哪幾段」每段一列，格式固定 `- <段 id>：<做了什麼>`（沒做的寫理由；剪輯台讀這一列，把修改單上那段標「✓ 已改」、可以點「看結果」，所以 id 照修改單的寫、一段一列）。
- 回報（≤ 15 行）每段一行「<段>：<做了什麼>」，加「剪輯台的修改單可以按『清空修改單』」，最後一行是停點 ④。
- 工具呼叫預算：每段算回饋輪的一項（6 次），動畫段另計（一段 18 次）。
