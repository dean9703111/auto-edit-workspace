# 發布手機確認頁（流程 H）

給 `auto-edit-review` 流程 H 用。使用者要在手機上看每一段（出門、遠端），說「手機確認頁」「把每一段動畫最後一格發布成網頁」時照這份做。頁面是固定模板，資料由工具塞進去：不要自己寫版面，也不要改產生出來的 `index.html`。

## 1. 產生

```
node shared/template/tools/versions.mjs site --project projects/<專案>
```

| 使用者說 | 加什麼 |
|---|---|
| 全部、每一段 | 不用加（字卡、動畫、錄影段都放，錄影段標成錄影） |
| 這一輪改的、剛改的那幾段 | `--round` |
| 指名幾段（「s05、x12」） | `--only s05,x12` |

每段一張卡：段號、動畫是什麼、完成影片時間、最後一格（點了放大）、對應字幕（收合）、想怎麼改（和剪輯台修改單同一套選項，動畫段可以勾「重新設計」）、想調整。填的存在那支手機；最下面「複製提示詞」只收有填的段，複製整份修改單。

最後一格沿用完成態截圖，沒有、或比那段的動畫檔舊的段它會自己補截（印「補截 N 段…」）。印 ⚠「補截沒有成功」：照它的 → 做一次（多半是要先跑 build），還是失敗就照樣發布，回報裡寫哪幾段沒有圖。

## 2. 發布

只發布 `work/site/index.html` 這一個檔（圖片都內嵌在裡面）：用平台的網頁發布功能（例 MiniMax 的 Site、Claude Code 的 Artifact）。不能發布就給檔案路徑，電腦上用瀏覽器打開一樣能用。回覆的最後兩行：

```
手機確認頁：<網址>
請回：在手機上每段點想怎麼改、寫想調整的地方，按最下面「複製提示詞」貼回來
```

## 3. 收到貼回來的修改單

貼回來的開頭是「# 剪輯台修改單」、第三行寫「這份是從手機確認頁複製的整份修改單」：照那一行，先把整份原文原封不動存成 `work/feedback/editor-requests.md`（覆寫），再照流程 F 做（`references/editor-requests.md`）。
