### 1.3 留下來的判準（五條都要過）

1. **口播訊號明確**：看得出「講到哪一句會用它」，而且教學片常講（每集至少可能出現一次）。
2. **能綁句**：每個新資訊一拍，拍點可以寫成 `P.at('#N@詞')`（F4：主文字出現＝講到那個詞，差 ≤ 0.5 秒）。
3. **完成態停得住**：最後一幕是靜止、完整、可讀的畫面（style.md「節奏」：新訊息 ≥ 1.2 秒、最後一幕 ≥ 1.5 秒）。
4. **只用 kit**：gsap timeline＋`SceneMotion` 的 P.*、`scene.css` class、brand／theme token、`kit/icons.json` 圖示；1920×1080；fullscreen 不壓右下子母畫面（`PIP_ZONE` x 1424–1888、y 581–951，主卡右緣 ≤ 1300）、不進字幕區（y ≥ 920）。
5. **和現有庫存不重複**：18 個情境（01–15、04a–04d）、9 支 custom（x-process／metaphor／before-after／numbers／warnings／prompt／ui-mock／architecture／branch）、40 張 fx 都對過；重疊的只收「補空缺的那一面」（例：`x-ui-mock` 已有單則通知，`x-notify` 只做「多則堆疊」）。

## 2. 候選 16 支

每支欄位固定：檔名｜口播訊號（例句：有 `#N` 的是 `projects/範例/work/rough.srt` 的真句，沒有的是自擬）｜版面｜靈感來源｜要移植的技法｜P.* 做法｜slots｜綁句與 D 下限估算｜風險｜弱模型為什麼填得動。D 下限的通則：fullscreen 0.5 秒前不動；D ≥ 最後一拍＋該拍動作長度＋最後一幕 1.5＋build 淡出 0.5。

### 2.1 ★ `x-checklist`：打勾完成清單（04a 替代）

- **口播訊號**：一組「要確認／要完成」的事，講一項勾一項；講完常接「這樣就全部好了」。
  - 「包含新增專案、下載 APP、配對手機、調整解析度等細節」（#66–#67）
  - 「確認畫面、聲音符合自己的需求」（#13–#14）；「讓我確認畫面的角度、光暗」（#56–#57）
- **版面**：fullscreen（子母畫面）。
- **靈感**：`koushikde-937635`（_koushikde_，https://x.com/_koushikde_/status/2105730717455937635，explainer，無標籤）「每一項先證明再打勾、量表逐條填滿」；`mattbean-917572`（mattbean，https://x.com/mattbean/status/2103146389412917572，motion，canvas）手繪表單逐欄打勾＋「Run test ✔ Passed」；`n01ennn-597182`（N01ennn，https://x.com/N01ennn/status/2108520767092597182，motion）「修完回饋、以綠勾收尾」。
- **技法**：① 筆記本式清單：一開始只畫出空框與橫線（告訴觀眾有幾項，但不先爆雷文字）；② 講到哪項，文字浮出、框裡描出勾；③ 底部進度條＋「2 / 4」計數同步前進；④ 全部完成時進度條換成完成色。
- **P.***：`P.stroke`（空框、橫線、勾）、`P.rise`（項目文字）、`P.in`（框亮起，疊層）、`P.count`（`suffix: ' / 4'`）、`P.bar`（進度）。
- **slots**：標題（≤ 10 字）、項目文字 ×2–4（≤ 14 字）。共 ≤ 5 個文字欄；沒有圖示欄（勾就是圖示）。
- **綁句**：`T = [P.at('#N@項目詞'), …]` 每項一個；選用 `ALL`。D 下限：T1 ≥ 2.2；相鄰 ≥ 2.1；D ≥ 最後一拍 + 2.9（有 ALL：ALL ≥ 最後一項 + 2.1、D ≥ ALL + 2.5）。
- **風險**：項目 > 4 要拆段；「總結」語意和 11 重疊——規則：講「確認／完成」用 x-checklist，講「回顧剛剛講過的」用 11。勾只用在完成／確認，流程站不勾（SITUATIONS §5）。
- **弱模型**：只改文字與句號；項數＝綁句陣列 `T` 的個數，進度比例、「/ 4」的分母都由 script 算。

### 2.2 ★ `x-timeline`：時間軸／歷史演進／本集大綱（04a 替代）

- **口播訊號**：有先後時間的 3–4 個節點（年份、版本、第幾部分）。
  - 「這集影片我會分成三個部分，先帶大家實際操作這個工具……接著說明如何安裝工具……最後分享我如何用 AI Coding 在短時間完成產品原型」（#64–#71，現在是 04a s23）
  - 「2019 年我開始拍片，2022 年改用手機錄影，今年把剪輯交給 AI」（自擬）
- **版面**：fullscreen。
- **靈感**：`rpa-dake-593915`（rpa_dake，https://x.com/rpa_dake/status/2104466394859593915，explainer，svg）大年號＋線畫圖示逐年描出＋底部進度點；`kloss-xyz-067876`（kloss_xyz，https://x.com/kloss_xyz/status/2103652674336067876，explainer，canvas/svg/css）「03 / THE NAME」節點索引＋一句年代說明；`airobertdaily-416945`（aiRobertDaily，https://x.com/aiRobertDaily/status/2108596616756416945，motion）「1976 → 2026」起訖對照。
- **技法**：① 先畫出橫軸與空心節點；② 講到哪個時間點，主色進度沿軸「走」到那個點（0.4 秒）、節點填滿；③ 節點上方卡片浮出（圖示＋年份／序號），下方一行說明；④ 目前節點有主色框，走過的節點保留實心點、框拿掉。
- **P.***：`P.stroke`（軸、空心點、實心點用粗描邊畫）、`P.bar`（進度沿軸）、`P.rise`、`P.icon`、`P.in`／`P.out`（目前框）。
- **slots**：標題、每個節點：標籤（4 位數字或 ≤ 2 字）＋說明（≤ 8 字、≤ 2 行）＋圖示。4 節點時文字欄 = 1＋4×2 = 9 → **超過 6**；所以首批規格把「標籤」定成可選（大綱變體用固定的 01／02／03，不用改），弱模型實際要改的是標題＋說明 ×3–4。
- **綁句**：`T1..T4`。D 下限：T1 ≥ 2.1；相鄰 ≥ 2.5（進度提早 0.4 秒出發）；D ≥ 最後一拍 + 2.9。
- **風險**：節點 > 4 放不下（卡寬 256）→ 拆兩段；年份 + 說明都很長的歷史題材要縮文案；原片的 3D 翻轉年號改成 `P.rise`。
- **弱模型**：節點位置、進度比例寫在 script 的 `X` 表，3／4 節點各給一組現成數字（spec 的變體表），不用自己算。

### 2.3 ★ `x-versus`：A vs B 動態比較（蝴蝶長條）

- **口播訊號**：兩個選項在 2–3 個面向上比，有數字或有高下。
  - 「如果只用一支手機錄影，可以用手勢控制開始跟結束，但如果要用兩支以上的手機同時錄影，就很難讓它們同時啟動」（#37–#40）
  - 「手動剪一支要 180 分鐘，用 AI 只要 20 分鐘；手動要 6 個步驟，AI 只剩 2 個」（自擬）
- **版面**：fullscreen。
- **靈感**：`n01ennn-597182`（同上）三個模型並排、各自計時器與長條同時跑；`dys-hay-749645`（Dys_hay，https://x.com/Dys_hay/status/2103819139307749645，motion，canvas/svg）「91 km/h」與「3.0 s」兩個數字同時跑；`threeaus-886343`（threeaus，https://x.com/threeaus/status/2105152377057886343，interactive）上下兩家對照、開關切換。
- **技法**：① 上方兩個對手（圖示＋名稱），中間 VS；② 每個面向一列：中間是面向名稱，A 的長條往左長、B 的往右長（蝴蝶圖），數字同步計數；③ 贏的那邊是主色、輸的是灰；④ 選用：講結論時贏家標頭亮框。
- **P.***：`P.rise`（標頭、列）、`P.morph` width 0→w（往左長的條用右錨定，所以不用 `P.bar`）、`P.count`、`P.in`（贏家框）。
- **slots**：標題、A 名稱（≤ 4 字）、B 名稱（≤ 4 字）、面向 ×2–3（≤ 4 字，單位寫進面向名，例「分鐘」）＝ ≤ 6 個文字欄；數字與贏家在 `DATA`。
- **綁句**：`T1..T3`（每列）、選用 `WIN`。D 下限：T1 ≥ 2.0；相鄰 ≥ 2.2；D ≥ 最後一列 + 3.0（有 WIN：WIN ≥ 最後一列 + 2.2、D ≥ WIN + 2.5）。
- **風險**：兩邊數字差 > 20 倍時小的那條幾乎看不到 → 最小寬度 8 px；沒有數字、只有「有／沒有」的比較用 04b。
- **弱模型**：數字只寫在 `DATA`（`{ a: 180, b: 20, win: 'b' }`），長度由 script 依該列最大值算；改的是名稱、面向、句號。

### 2.4 ★ `x-stack`：架構堆疊（13 替代）

- **口播訊號**：一層疊一層的組成，從底層講起；每層「名稱＋一句說明」。
  - 「最底層是手機上的錄影 App，中間靠區網連線，最上層才是電腦端的控制台」（自擬，對應 #54–#58 的工具架構）
  - 「這個網站分三層：資料庫存影片資訊、後端 API 負責轉檔、前端給你操作」（自擬）
- **版面**：fullscreen。

- **P.***：`P.drift`、`P.rise`、`P.type`（短回答可打字）、`P.bar`（底線）。
- **slots**：標題、泡泡 ×2–4（每則 ≤ 16 字、≤ 2 行）＝ ≤ 5。
- **綁句**：`B1..B4`。D 下限估：B1 ≥ 1.5；相鄰 ≥ 2.0（打字的那則 ≥ 字數 ÷ 8.5 + 1.2）；D ≥ 最後一則 + 2.8。
- **風險**：和 `x-prompt` 分工：一段提示詞用 x-prompt，有來有回的對話用 x-chat；泡泡文字不要逐字照抄字幕（style.md「字卡文字」）。
- **弱模型**：泡泡是兩種固定 class（`--me`／`--ai`），複製即可。

### 2.14 `x-zoom`：放大檢視

- **口播訊號**：「手機上看不出來，放大才看到」「注意看這一行」，而且沒有螢幕錄影可以用 media 段放大鏡。
  - 「但畢竟手機畫面較小，很多小毛病是把影片放到電腦上才會發現的，像腳架不穩造成畫面輕微晃動」（#18–#22，現在是 07 s07＋12 s08）
  - 「放大看這一行設定，port 一定要填 8080」（自擬）
- **版面**：fullscreen。
- **靈感**：大部分自己設計。參考 `twoclipping-747965`（同上）gotchas「相機 zoom 進偏心的點會甩，改成把點打開」；`dale-vaz-879074`（dale_vaz，https://x.com/dale_vaz/status/2103290592679879074，motion，canvas）多尺度放大到一個數字「25」。
- **技法**：① 左邊一個小螢幕（示意內容：幾行文字或圖示格）；② 圓形放大鏡移到第一個位置，鏡內是 2 倍的同一份內容（兩層同步 `P.morph` 位置）；③ 旁邊標註文字浮出；④ 移到第二個位置。
- **P.***：`P.morph`（鏡框與鏡內內容的 left／top 反向同步）、`P.rise`、`P.stroke`。
- **slots**：標題、示意內容（≤ 4 行）、標註 ×2（≤ 6 字）＝ 4–7。
- **綁句**：`Z1`、`Z2`。D 下限估：Z1 ≥ 2.0；Z2 ≥ Z1 + 2.5；D ≥ Z2 + 3.0。
- **風險**：鏡內內容要複製一份 DOM（兩份文字要同步改）→ 弱模型容易只改一份；放大倍率與位置要算（給固定 2 個錨點）；所以排在後面。
- **弱模型**：只能給「固定兩個位置」版本；要自由位置的不做。

### 2.15 `x-tiles`：翻牌預告（12／04a 替代）

- **口播訊號**：先預告數量「接下來有四個小技巧」，再一個一個講。
  - 「這集影片我會分成三個部分」（#64，接著逐項講）
  - 「接下來分享四個我每次開拍前都會做的小動作」（自擬）
- **版面**：fullscreen。
- **靈感**：`fleyta88-443662`（fleyta88，https://x.com/fleyta88/status/2108249741125443662，explainer）UI 卡片的錯開節奏（卡 280 ms、標題 220 ms、資料 160 ms、錯開 60 ms，逐格驗證）；`twoclipping-402193`（twoclipping，https://x.com/twoclipping/status/2103273003555402193，motion，svg）「同一個形狀不換、只換裡面的內容」。
- **技法**：① 一排 3–4 張蓋著的牌（只有 01／02／03／04，0.5 秒一張）；② 講到哪項，那張「翻開」：牌背 `P.swap` 成牌面（圖示＋≤ 6 字），不做 3D 旋轉；③ 目前這張主色框。
- **P.***：`P.rise`、`P.swap`、`P.icon`、`P.focus`。
- **slots**：標題、牌面 ×3–4（≤ 6 字）＝ ≤ 5。
- **綁句**：`T1..T4`。D 下限估：T1 ≥ 2.5（四張牌背 0.5 秒一張）；相鄰 ≥ 2.0；D ≥ 最後一張 + 2.9。
- **風險**：牌背預告要花 2 秒，短段落吃不消；和 x-callout、x-checklist 功能接近 → 排在後面。
- **弱模型**：固定 4 張，刪一張的表。

### 2.16 `x-conveyor`：流水線（同一個東西經過幾個工站、樣子跟著變）

- **口播訊號**：「影片丟進去，先轉成逐字稿，再挑 NG，最後輸出初剪」——重點是**同一份檔案**在每站變成什麼。
  - 「影片丟進去，先轉成逐字稿，再自動挑出 NG，最後輸出初剪」（自擬）
  - 「錄好的檔案會先備份、再轉檔、最後上傳」（自擬）
- **版面**：fullscreen。
- **靈感**：`stokebuilder-356793`（同上）海報：一排文件從中間的掃描機穿過；`notdwd-766641`（notdwd，https://x.com/notdwd/status/2105031774904766641，motion）膠卷格逐格蓋上、播放頭掃過；`0xlangeai-178533`（同上）四個工站框＋箭頭。
- **技法**：① 一條直線軌道＋ 3 個工站框；② 檔案方塊沿軌道走（`P.morph` left），進站時圖示 `P.swap` 換成新樣子（影片→文件→剪刀）；③ 走過的站換框色。
- **P.***：`P.morph`、`P.swap`、`P.in`、`P.stroke`。
- **slots**：標題、工站 ×3（≤ 4 字）、檔案每站的名稱 ×3（選填）＝ 4–7。
- **綁句**：`S1..S3`。D 下限估：S1 ≥ 2.0；相鄰 ≥ 2.4；D ≥ 最後一站 + 2.9。
- **風險**：和 `x-process`（站逐步亮起）功能重疊最多，差別只在「有一個東西在走、樣子會變」→ 排最後；只在檔案狀態變化是重點時用。
- **弱模型**：固定 3 站。
