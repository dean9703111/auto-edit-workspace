# 085 改字幕不用懂句號

## 作者原話（minimax-ep1，2026-11-23）

- 「我覺得目前字幕的 UIUX 體驗不佳，改句號這些正常人哪裡會知道，我們就是直接調整了」

## 發生了什麼

1. 剪輯台刪一句有東西綁著的字幕，會跳視窗要選「改綁到前一句／後一句」，列出 `#98@讀到` 這種句號。
2. 刪掉重複的「可以讀到一百萬」之後，plan.json 有 21 處沒有跟著 −1：第一層的 `outro.from`、`sections[].at`（本集地圖），錄影段的 `clicks`（字串陣列）、段落的 `sfx` 物件（`sfx` 在略過清單裡）。
3. 改字把 `#435@剪輯的成` 的「成」改掉（「剪輯的成本和能力門檻」→「剪輯的門檻」），動畫檔的 `P.at` 找不到詞，build ✖，使用者看不懂。

## 定案

- **刪除不用選**：不帶 `bind` 的 delete＝綁著的時間留在原本那一刻，寫成比較近的一邊（前一句結尾＋秒數或後一句開頭−秒數）；`#k@詞` 的詞在前一句或後一句也有就改綁那一句。`bind: "prev"／"next"` 是舊寫法，照舊。剪輯台拿掉改綁視窗，直接刪、toast 說「跟著它的畫面留在原本的時間」。
- **詞不見了自動接**：改字之後詞在那一句和隔壁句都找不到，就綁那一句還留著的開頭幾個字（≥ 2 字），再不行就綁原本那一刻（`#N+秒`）。
- **一個地方算**：`editor/subtitles.mjs` 的 `stepRef`／`stepPlan`；頁面（`doSrtOp`、`setCue`、尋找與取代）、存檔重播（`replay`）、鏡位腳本與動畫檔（`lib/beat-remap.mjs` `opsMapper`）都用它。打字時一個字一個字的 set 會併成一個，頁面從併之前的狀態整段重算，和存檔算的一樣。
- **欄位補齊**：`mapPlanTimes` 也換第一層其他欄位（`edit`、`captionMarks`、`moods`、`scenes` 以外）；整串都是句號的陣列（`clicks`）；`sfx` 拿出略過清單（音效名稱字串不受影響，只換物件裡的 `at`）。
- 檢查面板「綁在這句的時間」改成「跟著這句出現的畫面」，只列段落 id，不列句號。

## 驗收

- `dev/tests/caption-auto-rebind.test.mjs`：用 minimax-ep1 的真實字幕重現三件事。
- `dev/tests/editor-subtitles.test.mjs`、`032-p3d.test.mjs`：刪除的舊斷言改成「不帶 bind 不報錯、時間不變」，舊寫法 prev／next 照舊。
