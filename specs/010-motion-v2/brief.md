# 010 動態設計 v2：主代理的診斷與任務說明

## 使用者原話（2026-10-31）

>
> 難道 sonnet 模型不知道這些好看的動畫如何做嗎？都已經有範例讓你參考了

## 主代理的結論

執行模型（Sonnet）完全照規則做了：規則要它「只改文字、圖示、句號」，動態由 `shared/template` 決定。所以完成影片的上限＝模板的上限。模板的動態是「資訊卡進場→停留→退場」的保守做法，沒有專業動態設計的要素。**要改的是模板層，不是規則層。** 改好之後任何模型跑出來都一樣好，這才是給弱模型用的工作區該有的設計。

## 專業動態（參考 reference 與剪映手法）有而我們沒有的

1. **層次與景深**：背景微視差、卡片有懸浮感（陰影／輕微 3D 傾斜）、前景粒子或光暈點綴。
2. **鏡頭**：推近關鍵元素（scale 1.0→1.06 的緩慢 push）、段落切換用 whip pan／zoom through／形狀遮罩，不是淡入淡出。
3. **字的動態**：關鍵字逐字彈出（back.out 過衝）、遮罩揭開、底線／螢光筆掃過、數字滾動帶尾音；標題與副標錯拍。
4. **持續微動**：圖示呼吸、線條流動（dash offset）、卡片 idle float，畫面任何 1 秒都有東西在動但不搶戲。
5. **焦點管理**：講到哪個元素就放大＋發光，其他壓暗／退後；完成後回到均衡。
6. **轉場語彙**：進出子母畫面時講者與卡片同時走位（講者縮小的同時卡片從講者位置長出）、章節轉場用色塊擦入＋標題重拍。
7. **節奏**：進場 0.35–0.5 s、強調 0.2 s、停留有微動、退場比進場快；每個拍點配音效；曲線統一（expo.out 進、power2.in 出、back.out 強調）。
8. **顏色與對比**：主色只用在焦點，其他降飽和；深色底的情境（金句、數字）用光暈。

## 硬限制（不能破）

- HyperFrames 逐格 seek gsap timeline 渲染：所有動態必須 timeline 驅動、確定性（亂序截圖相同）；不能用 rAF／Date／CSS animation 的時間流。Canvas 可用但每格由 progress 重畫。
- 零相依：只有 kit 的 gsap、scene.css、brand token、icons.json；字型 Noto Sans TC。
- 1920×1080；子母畫面右下 1424–1856×594–918 不能壓；字幕底條區不能壓；講者臉與手勢不能擋（speakerBox）。
- 弱模型只改文字／圖示／句號：所有新動態都要封裝成 SceneMotion `P.*` 原語或情境內建，不能要求執行模型寫動態。
- audit 規則（字級、stagger、D 下限、cue-text、static）照舊；新原語要能通過或同步更新規則。
- 效能：render 時間不超過現在 2 倍。

## 補充（2026-10-31 15:40，使用者：「小模型做不出好的情境動畫，問題在於沒有設計分鏡，應該先設計文字稿分鏡讓人確認後再生成」）

主代理判斷：這是流程層的缺口，和模板上限（上面的結論）是兩個互補的問題。模板 v2 決定「每個動作好不好看」；文字分鏡決定「對的時間做對的動作、觀眾該看哪裡」，而且把品味判斷提前到人看得懂、改得動的文字階段。兩個都要做。

### 動畫分鏡（beat sheet）的定義

每一段情境動畫在生成之前都有一張文字表，人確認後才生成；表的欄位固定：

| 拍 | 講到（綁句） | 畫面上出現什麼 | 動態（設計系統語彙） | 焦點（觀眾看哪） | 音效拍點 |
|---|---|---|---|---|---|
| 1 | `#12@錄影` | 四站骨架：錄影→逐字稿→剪輯清單→初剪 | 站依序 pop、連線描出 | 均衡 | whoosh |
| 2 | `#12@錄影`+0.3 | 站 1 | 焦點：放大＋發光，其他壓暗 | 站 1 | tick |
| … | | | | | |
| 完成 | `#15e` | 四站全亮 | 回均衡、idle 微動 | 整體 | success |

- 「動態」欄只能用 design-system.md 的語彙（進場／強調／焦點／轉場／微動的具名動作），不寫自由描述；弱模型是在**選**動作，不是在**發明**動作。
- 每個情境（SITUATIONS §3 的每一列）附一個**預設拍型**（default beat pattern）：弱模型照拍型填「講到哪個詞」和「出現什麼」就好；要改拍型的是人（在停點改表）。
- 字卡（06／07／12／13）不用分鏡：它們是固定兩拍（lead → key／逐條）；只有情境動畫（x-*）與 04 家族要。

### 進流程的位置（主代理建議，待使用者定）

- 併進**停點 ③ 分鏡表**：`work/storyboard.md` 每個情境動畫段落底下多一張「動畫分鏡」表；使用者一次確認版面＋分鏡。某段的情境在 ③ 被改掉時，只重出那一段的分鏡（狀態「修改後重停」）。不新增停點。
- `auto-edit-storyboard` 步驟 5 的情境判定表之後加「寫動畫分鏡（抄該情境的預設拍型，填詞與元素）」；`auto-edit-motion` 第一步改成「讀確認過的動畫分鏡，照拍逐行做」，不再從範例猜。
- audit 加「分鏡對齊」規則：分鏡表每一拍的綁句都要在 x-*.html 裡有同名的 `P.at` 與元素；動態欄的語彙要對到實際用的 `P.*` 原語；差 > 0.5 s 或缺拍 → ✖。這樣分鏡不是文件，是可驗證的契約。
