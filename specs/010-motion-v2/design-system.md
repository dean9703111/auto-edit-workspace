# 010 動態設計系統 v2

日期：2026-10-31。階段 A 產出（原型在 scratchpad，沒有改 `shared/`、`projects/`）。
讀者：階段 B 的實作者（002／003／004／001）與 009 直式。執行模型（弱模型）**不讀這份**：它只改文字、圖示、句號，動態全部由這份規定的 kit 原語與情境內建行為產生。

## 0. 三個核心決定

1. **動態的單位是「拍」，不是「元素」。** 每個綁句點（`P.at`）是一拍：進場（≤ 0.6 s，錯拍）→ 強調（0.2 s，過衝或光）→ 其他元素退焦 → 一顆音效。
   拍與拍之間由「微動」撐場（背景慢拉、光暈漂移、卡片漂浮、虛線流動），所以畫面任何一秒都有東西在動，但**同一時間只有一個焦點**。
2. **三層相對運動由 kit 自動給，執行模型一行都不用寫。** 背景環境層（`P.end()` 自動呼叫 `P.ambient`）、講者層（build 在疊加卡期間慢推、轉場時色帶擦開與子母畫面落地）、卡片層（情境模板與 custom 範例內建的編排）。
   層與層速度不同＝景深；焦點靠 `P.spot`（放大＋抬起＋發光＋其他壓暗）與 `P.cam`（鏡頭跟著焦點走）。
3. **亮暗兩套只換 token，構圖與動態共用。** `plan.json` 第一層 `"theme": "light" | "dark"` → build 在主合成 `<html>` 寫 `data-theme`；元件 CSS 只吃 `var(--v2-*)`。
   規則：**疊在實拍上永遠硬邊**（錯位底板＋一層淡落影，不發光）；**不透明幕上才允許柔光、光暈、漸層**；主色只給焦點。

## 2. 具名區域（位置一律用區域名；座標只在這張對照表）

原語參數、層次模型、轉場與焦點規則**只講區域名**。009 的 `canvas.mjs` 注入 `window.__regions = { 名稱: [x, y, w, h] }` 即可蓋過橫式預設（原型的 `REGION()` 已經這樣讀）。

| 區域 | 意思 | 橫式 1920×1080（預設） | 直式 1080×1920（009 定案值；其餘由 canvas.mjs 給） |
|---|---|---|---|
| `band` | 字卡帶（疊在講者上的下方字卡） | x 120–1800、y 600–860（07 卡底 860） | y 880–1240 |
| `panelTop` | 資訊面板（全畫面主卡） | x 120–1300、y 150–858（右緣避開 pip） | 上半 1080×900 |
| `panelBottom` | 講者面板 | 講者滿版（speakerBox 由 plan 給） | 下半講者 |
| `pip` | 子母畫面小視窗 | x 1424–1856、y 594–918（432×324） | canvas.mjs |
| `badge` | 章節角標 | 右上 x 1560–1880、y 40–140 | 左上 |

## 7. 焦點管理規則

1. 一組元素（站、時間點、條列）用 `P.spot(group, active, at)` 管；**group 只放已經進場的元素**（未進場的元素被壓暗會提前露出）。
2. 焦點：scale 1.06–1.08、抬起 −10u、亮框＋發光（`.sc-spot` 吃 `--v2-spot-glow`）、0.5 s power3.out。
3. 非焦點：未到 0.42–0.5、scale 0.96；走過（`done`）0.8–0.92、保留主色細框。疊加卡的前句在重點出現時 `P.dim` 到 0.62。
4. 新進場的元素先 `P.pop` 落地，**0.6 s 後**才 `P.spot` 抬起（同一屬性重疊的補間會互相覆蓋）。
5. 預覽態：一組全部出現後 0.5–1 s，`P.spot(group, 'none')` 全部退成預覽，讓觀眾知道「接下來要講這幾個」。
6. 鏡頭：焦點切換那一拍提早 0.2 s `P.cam(card, {to: 焦點, k: 0.12, scale: 1.04})`；位移上限 ≈ 50u，完成後不壓 `pip`、不進 `captions`。
7. 回均衡：最後一拍後 2.6 s（或段尾前 1.2–1.6 s，取早的）`P.spot(group, null)`＋`P.cam({x:0,y:0,scale:1})`。
8. 焦點拍的音效：`tick`（附加）；漣漪 `P.ripple` 只打在焦點的圖示或進度頭。

## 8. 微動規則

| 對象 | 原語 | 振幅／週期 | 何時 |
|---|---|---|---|
| 背景 | `P.ambient`（自動） | scale 6 %→0、光暈 60–90u／13–17 s、浮塵 ≤ 120u | 整段 |
| 卡片、焦點 | `P.idle` | y 3–4u、x ≤ 1.5u、2.8–3.6 s | 進場完成後 0.3 s 起，到下一拍前 0.1 s |
| 圖示 | `P.idle({scale})` | 4 %、1.8 s | 停留期 |
| 進度頭、小點 | `P.idle({scale})` | 12 %、1.4 s | 停留期 |
| 預告虛線 | `P.flow` | 24u／s | 出現到段尾 |
| 講者 | main 慢推 | 4.5 %／段長 | 疊加卡期間 |

上限：同一元素只掛一個 idle；字不單獨 idle（跟著卡）；頭尾 0.8 s 漸入漸出（不跳）；微動不算「新資訊」，不配音效。

## 11. 新 `P.*` 原語清單

全部 seek-safe。三種確定性做法：
**(a)** 一般進場仍是 `fromTo`，同元素同屬性第一個才 `immediateRender`（既有 `move()`）；
**(b)** 漣漪、彗星頭、長出、光澤、微動用純函式外掛 `scFn`：畫面只由 progress 算，0 與 1 都是定義好的狀態，**建立時先畫一次 progress 0**（timeline 的 `to()` 不保證立即 render）；函式放在登記表、補間值傳編號（GSAP 會把 vars 裡的函式，含巢狀物件裡的函式，當 function-based value 先呼叫）；
**(c)** 微動寫 CSS 個別屬性 `translate`／`scale`，不碰 GSAP 的 `transform`，和進場位移、`spot`、`cam` 互不覆蓋。
驗證：主合成用 `snapshot --at` 以兩種順序拍 5 個時刻（16.6／20.9／79.5／83.6／84.4 s，涵蓋抽屜、長出、漣漪、spot、cam、彗星），**全畫面逐像素相同（max diff 0）**。
