# 074 剪輯台改字幕後，動畫的句號跟著詞走、復原時一起換回去

## 作者原話（AI郵報宣傳 r7 之後，2026-11-20）

- 「調整字幕時『會左右並排』出現問題」「另外字幕不能使用分割的功能嗎？」
- 「字幕手動調整又卡住了」
- 「句號這個規則是不是有問題啊，因為目前字幕的斷字本身就有點問題」
- 選「先做 1 然後做 2」（1＝這一集先把斷句一次修好；2＝修工具）

## 發生了什麼

AI郵報宣傳在剪輯台調了兩次字幕，兩次都讓內容設計動畫的拍點綁錯句：

| 時間 | 字幕檔、plan.json | 動畫檔、鏡位腳本 |
|---|---|---|
| 01:21 | #16／#17 改斷句（45 → 46 句），plan.json 的句號都對 | s0107 `#17@流程` 變成 `#17`（詞不見）；s0108 `#18@放進` → `#17`（該是 `#19`）；s0114、s0118 沒動（該 +1） |
| 01:28 | 「都要你點頭」從第 25 句改字搬到第 26 句（句數不變），plan.json 的 `#25@要你點頭` 沒跟過去 | s0114、s0118 的句號 +2（該不動）→ 8 個 ✖，剪輯台不能更新預覽（作者說「卡住」） |

## 原因

1. **復原沒有把動畫檔換回去**：存檔時 `remapScriptsAfterSave` 會順便重對 `work/designs/<段>.md` 和 `x-design-*.html` 的句號，但 `/api/restore`（⌘Z）只換回 plan.json 和 rough.srt。「分割 → 復原 → 再分割」之後，plan.json 只 +1，動畫檔 +2。01:28 那次字幕和 plan.json 都回到同樣的句數，動畫檔卻多了 +2，就是這樣來的。
   - 單一步的分割、新增、合併、刪除，`opsMapper` 都對（測試重現過）。只有存檔這一個地方會改動畫檔的句號。
2. **改字把詞搬到隔壁句時，`#N@詞` 不會跟過去**：只有增刪字幕（split／insert／merge／delete）會重對句號；`set` 改字不管詞還在不在那一句。plan.json 和動畫檔都一樣。

（之前回報的「x0109 註解被改成 `#461@確認`」是誤判：那是 `custom/x-point.html` 模板本身的範例句號，不是 bug。）

## 定案

- **復原、重做跟著換回去**（`editor.mjs`）：
  - 存檔時 `remapScripts` 回傳每個改到的檔改之前、之後的內容（`changes`）。服務記一步 `{ from, to, files }`（`from`／`to` 是存檔前後的 plan.json＋rough.srt 版本），最多 200 步，跟復原用的舊版本一樣只在記憶體。
  - `/api/restore` 換好 plan.json、rough.srt 之後，從現在的版本走到要回去的版本（可以跨好幾步，往回用 before、往前用 after）把這些檔換回去。
  - 檔案現在的內容和那一步預期的不一樣（存檔之後 AI 又改過）就不動，回應的 `scripts.skipped` 列出來，服務印 ⚠。
- **`#N@詞` 跟著詞走**（`subtitles.mjs followKw`／`followPlanKw`）：
  - 每做一步字幕操作（增刪字幕，或 `set` 改了字），第 N 句已經沒有這個詞、而前一句或後一句只有一句有，就改綁那一句。兩句都有、都沒有就不動（build 照樣報 ✖，不猜）。
  - 每一步都算，不是全部做完才算：頁面（`app.js` 的 `doSrtOp`、`setCue`、尋找與取代）邊改邊更新段落的句號，伺服器存檔用 `replay` 重放，兩邊要算出一樣的結果，不然頁面會把舊的句號當成「使用者改的」送回來。
  - 動畫檔、鏡位腳本（`beat-remap.mjs opsMapper`）同一個時機。只改字的存檔也會跑 `remapScriptsAfterSave`（以前只有增刪字幕才跑）。
- 文件：`shared/template/EDITOR.md` 第 3 節表格的句號那一列、第 4 節加「`#N@詞` 跟著詞走」。

## 不做

- 不改綁句的寫法（`#N@詞` 照舊）。改成只綁詞、不綁句號，要動 build、audit、分鏡表、設計師文件，這次先把剪輯台修對。
- 不把動畫檔改動存進磁碟：和 plan.json、rough.srt 的復原版本一樣只在服務記憶體，剪輯台重開就回不去（照舊說「更早的步驟回不去了」）。
