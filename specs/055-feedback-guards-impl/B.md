## Q2 起始鏡位 `start`

**寫法**：`"start": [x, y, w, h]`，素材像素，和 `moves.to` 同一套。

**畫面行為**

- 第一格就推在這一塊，沒有推的動作。`mediaParts` 在段起點 `tl.set('#mst-<id>', { x, y, scale, force3D: false }, <段起點>)`。
- 之後的 `moves` 從 start 的鏡位出發；寫 `"full"` 拉回全景。
- 框照 `moves.to` 的算法放進可見區（`camFor`）。
- 框比可見區高、照比例放不進去（就是短影片5 m0103「框比畫面還大，推不近」那種）時：
  - 改成撐滿寬度：倍率＝可見區寬 ÷ 框寬，框的上緣對齊可見區上緣。
  - 左右空白裁掉，上下多出來的裁在下面。
  - 報告寫「起始鏡位 N 倍（撐滿寬度，框的下面裁掉）」。

**拿掉、改掉的 ⚠**

- 拿掉了「第一次運鏡要在段起點 0.8 秒後」（`MOVE.lead`）。
- `moves[0]` 在段起點 0.3 秒內、`dur` ≤ 0.3（舊的「0.2 秒硬推」寫法）：
  - 不再報「太快」，也不算進運鏡次數。
  - 改報：`moves[0] 在段起點就推（0.2s），其實是起始鏡位 → 改寫成 "start": [x, y, w, h]、拿掉這個 moves（第一格就在那一塊，沒有推的動作）`。
- `moves[0].to` 推不近，而框比畫面窄時，訊息後面多一句：`；要一開始就裁掉左右空白，改寫成 "start"（框比畫面高時撐滿寬度）`。

**新的 ⚠**

- 寬高都比畫面大時：`start 的框 [..] 寬高都比畫面大，推不近（第一格和沒寫 start 一樣）→ 只框要看的那一塊（至少比畫面窄），或拿掉 start`。
- 有 start 的圖片不做 Ken Burns 慢推。寫了 `"kenburns": true` 時 ⚠：`kenburns：有 start 時不做慢推（Ken Burns），已忽略`。

**--check --json**

- `view.scale` 改成第一格的倍率：素材縮放 × start 推近。`specs/contracts/check-json.md` 還沒寫（G）。

## C16 隱私（k20）

**盤點筆記的寫法**

- 在 `work/media/notes/<檔名>.json` 加 `privacy: [{ from, to, box, what }]`：
  - `from`／`to` 是錄影秒數，不寫＝整段；
  - `box` 是素材像素。
- 錄影的筆記是一個物件、圖片一批是陣列，都用 `file` 對到素材。

**判斷**：每 0.1 秒看一次，下面都成立的那一格才算露出。累計 > 0.1 秒（`PRIVACY.tol`）才報。

- 隱私框在畫面上：運鏡推走、看不到的不算。
- 沒有一個正在作用的 `redact` 蓋住它 ≥ 90%（`PRIVACY.cover`）。

**訊息**：`錄影 4.9–7.9 秒露出「帳號名（路徑選單）」[900, 575, 340, 62]（完成影片 1:16.18–1:18.18）沒有打碼 → 加 "redact": [{ "at": "+3", "until": "+5", "box": [900, 575, 340, 62] }]`
