# 009 直式短影片：研究（research）

- 日期：2026-10-31
- 範圍：直式（9:16、1080×1920）口播短影片的平台慣例、安全區、版面對照、字幕／角標／金句／媒體標註的位置、橫式素材裁直式的方法；外加現有程式「寫死 1920×1080」的盤點，給 `spec.md` 用。
- 數字一律是 **1080×1920 畫面像素**。標「建議初值」的數字要用 `projects/範例-直式` 試跑後再調（spec 的驗證計畫）。

## 0. 結論先講

1. **分歧只在一個地方決定**：開工決策表多一列「版式」，寫進 plan.json 第一層 `"format": "portrait"`。之後六個停點、Skill 流程、指令都一樣；差異收進一份「畫布設定」（`tools/lib/canvas.mjs`，橫式一組、直式一組數字），所有工具都從那裡讀。
2. **直式只有三種版面**：疊加（講者滿版＋卡片帶）、**上下分割**（上半資訊、下半講者，取代子母畫面）、全幕。半畫面（03）與兩側（05）直式不提供。
3. **不重寫 17 支 custom 與 04 家族**：它們的主卡都排在 1920 舞台的同一個框（x 120–1300、y 130–880）。直式時 build 把整個 1920×1080 子合成等比縮 0.8475 放進上半面板（x 40–1040、y 240–876）。上半面板的寬高比（1000×636＝1.57）和主卡框（1180×750＝1.57）一樣，所以縮放不會浪費空間；改寫成 CSS 變數得不到更好的版面，成本卻是 13–17 小時（§6）。
4. **下方字卡（06–11、13–15）只換位置**：橫式卡寬上限 900（x 120–1020），直式卡片帶 x 60–940 剛好 880，slots 字數上限幾乎不用改。
5. **字幕要縮**：直式字幕 60 px、一行、**每則 ≤ 12 字**（橫式 18 字），固定在 y 1302–1390。

## 1. 平台慣例（YouTube Shorts／Instagram Reels／TikTok）

三個平台都是 1080×1920 上傳，畫面上都疊了平台介面：

| 位置 | 疊了什麼 | 三個平台 |
|---|---|---|
| 頂部 | 狀態列、「追蹤中／為你推薦」分頁、搜尋、Reels 標題與相機 | 都有，TikTok 最高 |
| 底部 | 帳號名、說明文字、音樂、（Shorts）訂閱鈕、導覽列 | 都有，最占空間；說明文字展開時更高 |
| 右側 | 頭像、讚、留言、分享、收藏、音樂唱片的直排按鈕列 | 都有，從畫面中段往下 |
| 左側 | 幾乎沒有 | — |

各來源的安全區數字差很多，**沒有任何一個是平台官方規格**（下表都是第三方整理）：

| 來源 | 頂部 | 底部 | 右側 | 左側 | 備註 |
|---|---|---|---|---|---|
| Revid.ai（TikTok） | 220 | 480 | 140 | 60 | 內容區 880×1220 |
| Socialync（TikTok） | 240 | 660 | 120（按鈕列 180 寬、y 840 起） | 120 | |
| Socialync（Shorts） | 288 | 672 | 192 | 48 | |
| Ignite Social Media（Reels，含廣告） | 220 | 420 | — | — | 1010×1280 |
| Keywords Everywhere（Reels） | 220 | 420 | 130 | — | |
| PostPlanify（Shorts） | 120 | 300 | — | — | 888×1500 |
| AdaptlyPost（跨平台） | — | — | — | — | 置中 900×1400 |
| Reap（跨平台，百分比） | 15 %（288） | 25–35 %（480–672） | 10–15 % | 10–15 % | 「最低的 1/4 不放重要文字」 |

字幕慣例（多數是剪輯工具廠商的部落格，品質參差）：放在中段偏下、避開底部 UI；粗黑體、白字加黑底或黑邊；一次 1 行、字少；寧可拆句也不要縮字。分割畫面（上下各一個畫面）主要用在雙人對談與「上螢幕錄影、下講者」的教學片，字幕常放在兩半交界或下半講者胸前。

### 1.1 本工作區採用的安全區（取保守值，建議初值）

| 區域 | 範圍（x1, y1, x2, y2） | 規則 |
|---|---|---|
| 平台頂部 UI | 0, 0, 1080, 240 | 不放文字、不放臉；講者頭頂以上的牆、背景圖可以 |
| 平台底部 UI | 0, 1440, 1080, 1920 | 不放文字；講者的身體、桌面可以 |
| 右側按鈕列 | 940, 840, 1080, 1440 | 不放文字、不放臉 |
| 左右邊距 | x < 60、x > 1020 | 不放文字 |
| **文字安全區** | y 240–840：x 60–1020；y 840–1440：x 60–940 | 所有卡片、角標、字幕都在這裡 |

取值理由：頂部 240 是 Revid／Socialync TikTok 與 Reels 220 的上緣；底部 480（y 1440）是 Revid TikTok 與 Reap「最低 1/4」的交集，比 Reels 的 420 保守，比 Socialync 的 660–672 寬鬆（660 會讓字幕只能放到 y 1260，壓到臉的機率大增）；右側按鈕列 140 寬、y 840 起取 Socialync 的起點與 Revid 的寬度。和平台實際 UI 的差距由「卡片離安全區邊緣再留 20 px」吸收。

```
直式安全區（1 格 ≈ 60×120 px）
x: 0       540      1080
   +-------------------+ 0
   |  platform top UI  |   不放文字
   +-------------------+ 240
   |                   |
   |   text safe       |   x 60–1020
   |                   |
   |                 +-+ 840
   |   text safe     |R|   x 60–940；R＝右側按鈕列 940–1080
   |                 |R|
   |                 |R|
   +-------------------+ 1440
   |  platform bottom  |   不放文字（身體可以）
   +-------------------+ 1920
```

## 2. 版面對照（橫式四種 → 直式三種）

| 橫式版面 | 直式版面 | 直式畫面 | 講者在哪 | build 怎麼做 |
|---|---|---|---|---|
| 疊加 | **疊加** | 講者滿版 1080×1920，透明卡在「卡片帶」 | 原位滿版 | 下方字卡換位置（§3.2） |
| 半畫面（03） | **不提供** | — | — | `--check` ✖ → 改 13 標題條列或 04a（上下分割） |
| 子母畫面（04a–d、custom fullscreen、media） | **上下分割** | 上半 1080×900 資訊、下半 1080×1020 講者 | 下半面板（滿寬裁切） | 子合成整個縮 0.8475 放進上半；講者面板用現有子母畫面那支靜音複本、換幾何 |
| 全幕（01、fx 不透明底） | **全幕** | 不透明 1080×1920 | 看不到 | 1920 舞台縮放置中，backdrop 補滿 |

`--check --json` 的 `layoutZh` 直式時是 疊加／上下分割／全幕；`layout` 機器值不變（`overlay`／`pip`／`full`），讀 check-json 的工具不用改分支。

### 2.1 疊加（直式）

```
x: 0       540      1080
   +-------------------+ 0
   |  top UI           |
   +-------------------+ 240
   | [02 badge]        |   章節角標 x 60–(寬隨章名) × y 250–362
   |      .---.        |
   |     ( o o )       |   講者臉（目標：頭頂 y 380–520、下巴 ≤ 860）
   |      `---'        |
   | +-------------+ +-+ 880
   | | card        | |R|   卡片帶 x 60–940 × y 880–1240（卡底 1240）
   | +-------------+ |R| 1240
   |   [ caption ]   |R|   字幕框 y 1302–1390（保留帶 1280–1420）
   +-------------------+ 1440
   |  bottom UI (body) |
   +-------------------+ 1920
```

- 下方字卡（06–10、13、14）：`left: 60px; bottom: 680px`（卡底 1240）。橫式是 `left: 120px; bottom: 220px`（卡底 860）。
- 置中卡（11 總結、15 金句）：在 x 60–940 之間置中（中線 x 500，不是 540：右側要讓按鈕列）。
- 卡片帶壓在講者胸前，不壓臉；手勢可能被壓到（直式講者滿版時手在 y 1300–1500，見 §5），碰撞照橫式規則只 ⚠、Studio 點名確認。

### 2.2 上下分割（取代子母畫面）

```
x: 0       540      1080
   +-------------------+ 0
   |  bg   (top UI)    |   backdrop：.sc-surface-fs 補滿 1080×900
   | +---------------+ | 240
   | | card window   | |   資訊窗 x 40–1040 × y 240–876
   | | 1920 stage    | |   ＝1920 舞台 [120,130,1300,880] × 0.8475
   | | x0.8475       | |
   | +---------------+ | 876
   +===================+ 900  分隔線（主色 6 px，取代 pip-frame.png）
   |      .---.        |
   |     ( o o )       |   講者面板 0–1080 × 900–1920（1080×1020）
   |      `---'      |R|   臉落在 y 940–1280
   |   [ caption ]   |R|   字幕框 y 1302–1390（壓在講者胸前）
   +-------------------+ 1440
   |  body (bottom UI) |
   +-------------------+ 1920
```

- 1920 舞台到直式的換算：`X = 40 + (x − 120) × 0.8475`、`Y = 240 + (y − 130) × 0.8475`；也就是子合成 host 加 `transform: translate(−61.7px, 129.8px) scale(0.8475)`（原點左上）。
- 舞台的可見範圍：x 73–1347、y −153–909（其餘被畫面邊緣或講者面板蓋住）。**內容要在 x 120–1300、y 130–880 內**，17 支 custom 與 04 家族現在都符合（主卡 left 120、寬 1180、top 139–185、卡底 ≤ 870）。
- 字級換算：56 → 47、52 → 44、40 → 34、30 → 25（最小字要另外 ⚠，§4）。
- 講者面板沿用現有子母畫面的機制（靜音複本、`pipCrop` 裁切、飛入、三層淡出），只換幾何：本體從 `1424,594,432×324` 變成 `0,900,1080×1020`，裁切框寬高比 1080:1020。「飛入」＝講者從滿版縮進下半面板，「講者不消失」（feedback r1 F2）自動成立。

### 2.3 全幕（直式）

```
   +-------------------+ 0
   | opaque backdrop   |   backdrop 1080×1920（fx 的 bg 色／bg-ch／bg-fs）
   |                   |
   | +---------------+ | 416
   | | 1920 stage    | |   fx：×0.5625 → 1080×608，置中 y 416–1024
   | | x0.5625       | |   01 章節：章名區 [160,260,1760,870] ×0.625，置中
   | +---------------+ | 1024
   |   [ caption ]     |   1302–1390
   +-------------------+ 1920
```

- fx 透明底（`bg: none`，疊在講者上）：同樣縮 0.5625，舞台放在 y 766–1374（中線 1070＝卡片帶中線）。橫式字幕區 y ≥ 920 換算過來剛好是 y 1283，和直式字幕保留帶上緣 1280 重合：**橫式不壓字幕的 fx，縮過來也不壓字幕**。

### 2.4 插入素材（media 段）

| fit | 橫式 | 直式（有講者面板） | 直式（`"pip": false` 或只有聲音的區間） |
|---|---|---|---|
| `contain` | 1920×940（字幕帶上方）置中 | 上半面板 x 0–1080 × y 240–900 置中（16:9 錄影＝1080×608，y 266–874） | x 0–1080 × y 240–1260 置中（手機直式錄影＝574×1020） |
| `cover` | 鋪滿 1920×1080 | 鋪滿上半面板 1080×900 | 鋪滿 1080×1920 |

- 標註（說明卡、紅框、聚光燈、箭頭、STEP 膠囊）的座標仍然寫「素材像素」，build 換算到直式畫面；自動擺位的避讓區換成直式的（字幕保留帶、講者面板、右側按鈕列）。
- 16:9 錄影縮到 1080 寬只剩原尺寸 56 %，介面字會很小：直式的錄影段**預設要推近到操作區**（`moves`）。qc storyboard 對「16:9 錄影、縮放 < 0.6、沒有推近、超過 3 秒」⚠。
- 手機直式錄影（9:16）在直式成片最自然：`"pip": false` ＋ `cover` 鋪滿，講者只留聲音。

### 2.5 半畫面（03）、兩側（05）：直式不提供

橫式 03：面板 960 寬＋講者右移 480        直式寬只有 1080
+----------+----------+                   +---------+
| panel    |  speaker |                   | panel?  |  面板 960 就占滿整個寬，
| 960x1080 |  (+480)  |                   | 960     |  講者沒有地方可以推
+----------+----------+                   +---------+

- 05 兩側（左右各兩張卡夾著講者）：直式兩側各只剩 0–300、780–1080，放不下 504 寬的卡 → 12 關鍵詞（橫排）或 13。

## 3. 子母畫面在直式：上下分割 vs 角落小窗

| 方案 | 畫面 | 優點 | 缺點 |
|---|---|---|---|
| **A 上下分割**（建議） | 上半資訊 1080×900、下半講者 1080×1020 滿寬 | 講者大、臉清楚；資訊窗 1000×636 和主卡同比例，04 家族與 17 支 custom 不用改；Shorts 教學片最常見的「上畫面下真人」；講者面板落在右側按鈕列與底部 UI 也不怕（那裡是身體） | 資訊窗比全螢幕小（字級 ×0.8475）；講者面板裁切要對準臉（§5 風險）；每次切換講者會從滿版縮進下半（0.7 秒，等同現在的飛入） |
| B 角落小窗 | 資訊滿版、講者 360×480 小窗 | 資訊區最大 | 小窗放右下會被按鈕列與底部 UI 蓋住；放左下壓到字幕；放上方壓到頂部 UI；講者臉變很小，違反「講者不消失」的精神 |
| C 上講者下資訊 | 反過來 | 臉在視線起點 | 資訊落在 y 1020–1440，被字幕與右側按鈕列切掉一大塊；底部 UI 蓋到卡片 |
| D 只有資訊（沒有講者） | 全幕 | 最簡單 | 違反使用者回饋 F2「人不應該突然消失」 |

**建議 A**，分割線 y 900（主代理原案是上 ~1000／下 ~920；改成 900／1020 是為了讓下半面板多 100 px，臉才能完整落在字幕框上方：臉 940–1280、字幕 1302 起）。

## 4. 字幕、角標、金句、媒體標註的位置

| 元件 | 橫式 | 直式（建議初值） | 理由 |
|---|---|---|---|
| 字幕 | 54 px、行高 64、框 y 940–1020、≤ 18 字、寬 ≤ 1600 | **60 px、行高 72、框 y 1302–1390（`bottom: 530px`）、≤ 12 字、框寬 ≤ 800（x 140–940）** | 底部 UI 從 1440 起；12 字 × 60＋內距 48＝768 ≤ 800。只排一行的規則不變 |
| 字幕保留帶（什麼都不放） | y ≥ 920 | **y 1280–1420** | `hyperframes check --caption-zone "x0=0;y0=0.667;x1=1;y1=0.74;severity=error"` |
| 章節角標（常駐／02） | 右上 x 1200–1824 × y 56–168 | **左上 x 60 起 × y 250–362**，從左滑入 | 右上有 TikTok 搜尋、Reels 相機；左上在三個平台都空。上下分割與全幕時隱藏（同 r1 F1） |
| 下方字卡 | x 120–1020 × y 536–860 | **x 60–940 × y 880–1240** | 臉的下方、字幕上方 |
| 金句（15）、總結（11） | 置中 x 510–1410 | **x 60–940 內置中（中線 500）** | 讓右側按鈕列 |
| 12 關鍵詞 | 左側直欄 x 120–560 × y 160–870 | **卡片帶內橫排膠囊（2×2 換行）** | 直欄會擋住講者半邊臉 |
| 全畫面清單／custom | 主卡 x 120–1300 × y 150–862 | **上半資訊窗 x 40–1040 × y 240–876** | 等比 0.8475 |
| 子母畫面 | x 1424–1856 × y 594–918 | **講者面板 0–1080 × 900–1920** | §3 |
| media STEP 膠囊 | 左上 | 上半面板左上（y ≥ 260） | 頂部 UI |

字級換算（手機實際大小）：iPhone 直拿時畫面寬約 393 pt。橫式影片直拿觀看（上下黑邊）時 1 px＝0.20 pt，橫式字幕 54 px＝11 pt；直式影片 1 px＝0.36 pt，直式字幕 60 px＝22 pt、縮放後的卡片字 47 px＝17 pt、custom 最小字 25 px＝9 pt。所以直式縮 0.8475 的卡片在手機上反而比橫式大，只有最小字（`.sc-t30`）會太小 → audit 在直式量「輸出像素」，< 32 px ⚠（建議初值）。

## 5. 橫式素材裁直式（P2；直式素材做橫式不在範圍）

| 方法 | 怎麼做 | 優點 | 缺點 |
|---|---|---|---|
| **A 固定裁切**（建議預設） | `qc.mjs framing` 以 speakerBox 中心算 9:16 直條：1.0＝整個高度（1080p 來源是 608×1080）、1.15／1.3 再放大；頭頂落在 y 380–520 | 穩、可預期、和現在的 `frame` 同一套（停點 ② 選倍率） | 講者左右移動大時會出框；1080p 來源要放大 1.78 倍（≤ 3.5 倍門檻內） |
| B 臉部跟隨 | 用 006 的 `work/face-landmarks.json`（每格臉框）算臉中心 x，1.5 秒移動平均＋5 % 寬度死區，產生分段線性的裁切路徑 | 講者走動也在框內 | 鏡頭會飄；要新工具（`look.mjs track`）；剪輯台要能看路徑 |
| C 寬視野講者面板 | 上下分割的講者面板從**原始橫式畫面**裁（不是從 9:16 直條裁） | 臉太大時可以拉遠，臉才能落在 940–1280 | 底片要保留橫式原檔（不能 bake 成 9:16），build 的底片編碼要分兩支或改用 CSS 裁切 |

建議：P2 先做 A（加 C 的 ⚠：講者面板放不下臉時給 `pipCrop` 建議）；B 等使用者有走動的素材再做（P3）。

## 6. custom 幾何：改寫成 CSS 變數 vs 舞台縮放

| 方案 | 做法 | 工作量 | 結果 |
|---|---|---|---|
| **舞台縮放**（建議） | build 給直式的 fullscreen 子合成 host 加 transform；子合成檔一個字不改 | build ＋ audit 規則約半天；17 支 0 改 | 版面和橫式一模一樣（同比例縮小） |
| CSS 變數／比例 | 每支把 left／top／width／height、svg 路徑改成 `calc(var(--W) …)` 或百分比 | 17 支 × 每支 14–27 個像素值＋svg 路徑＋檔頭【版面】說明，每支 45–60 分鐘（含兩種版式各跑 audit），合計 13–17 小時；驗過的範例全部要重驗 | 上半資訊窗和主卡同比例，排出來和縮放一樣；只有 `"pip": false` 的直式全畫面才用得到更高的空間 |
| 各給直式變體 | `x-timeline-v.html` 這類另寫一支 | 每支 1–1.5 小時 | 只在直式全畫面（沒有講者）時有意義 |

→ P1 用舞台縮放；P3 視試跑結果，對「直式全畫面、沒有講者」常用的 2–3 支（例：x-timeline 改直軸、x-process 改縱向）做變體。
