# 017 分鏡表網頁（停點 ③）

來源：作者 2026-11-06 說「這個也設計成網頁，背後資料依舊是 markdown，但我可以做內容編輯，這樣彈性更高；完成後也要截圖更新到 README 跟官網上」。

## 定案

| 題目 | 定案 | 理由 |
|---|---|---|
| 範圍 | 停點 ③ 的整份 `work/storyboard.md`，新頁 `/storyboard`；改版提案 `work/versions/<段>/v<N>/分鏡.md` 這次不動 | 作者指的是分鏡表；改版提案另一條流程，要做再加 |
| 真相在哪 | 仍是 `work/storyboard.md`；頁面每次只動改到的那幾行，其他字元原樣保留（含 CRLF、BOM） | `audit.mjs`、`versions.mjs`、`illus-lint` 和 AI 照舊讀檔 |
| 可以改什麼 | 欄位內容（冒號前的欄名不動）、表格的格、加減列、金句勾選（`☑`／`☐`）；要改結構用該段的「改原始 Markdown」 | 彈性來自原始 Markdown；日常修改不用碰語法 |
| 保護 | 表頭與段標題不能點來改（audit 逐字讀）；原始 Markdown 第一行要保留同一個標題；動畫分鏡表頭被改掉、段號重複時頁面顯示警告 | 改壞了工具會讀不到 |
| 存檔 | 離開欄位或按 Enter 就存，Esc 取消；存前比對檔案 hash，並比對那一格改之前的內容，對不上就不寫，沒存到的文字留在頁面上 | 沿用「被別人改過就不寫」；文字比勾選值錢，不能直接丟 |
| 只能看 | 製作進度「③ 分鏡表」最後一列是「通過」或「略過」；「修改後重停」「待回覆」又能改；改版的 `③ 分鏡表（s12 v2）` 不算 | 通過後已照這份寫正式 plan.json，再改不會生效 |
| 預設展開 | 需要決定的事、總覽、每段、動畫分鏡展開；四種版面、圖示表、情境判定、插圖清單收起 | 先看要決定的內容，參考資料要用再開 |
| 服務 | 沿用 `editor.mjs`，多一頁 `/storyboard`；啟動時多印「分鏡表：<網址>」 | 不新增指令與名詞 |

## 調整（2026-11-06，作者看過實際畫面後）

作者說「大家並不知道有哪些選項，或許有下拉選單會輕鬆一點，而修改原始 markdown 對大多數人也太難可以移除；只有要呈現的文字可以編輯就好，另外如果整段不滿意，可以在下面有對應調整的文字補充說明」。

| 題目 | 定案 | 理由 |
|---|---|---|
| 可以改什麼 | 只有畫面文字「」裡的字、動畫分鏡「畫面上出現什麼」、金句的卡上文字與勾選；取代上面「欄位內容、加減列、原始 Markdown」 | 其他欄位給工具和 AI 用，改了也看不出效果 |
| 下拉選單 | 呈現方式（情境＋情境動畫，照版面分組，附「看範例」連結與適用時機）、音效；選項從 `scenes/`、`custom/`、`kit/sfx.json` 讀 | 新增情境不用改頁面 |
| 換呈現方式 | 不改 `版面`，另外寫 `- 想換成：<情境>`；使用者說「可以」後 AI 重做、重截、刪掉這行、再停一次 | 截圖和文字要等 AI 重做才對得上，當成要求才不會謊報現況 |
| 不滿意整段 | 每段下面的補充說明，寫成 `- 補充說明：<文字>`，處理方式同上；「需要我決定的事」也有一格可以回答 | 不用懂格式就能表達 |
| 拿掉 | 改原始 Markdown、加減列（API 的 raw、addRow、delRow 一起拿掉） | 對大多數人太難 |

作者接著說「幫我優化，從使用者角度做出最好的選擇」，再收斂顯示（只動頁面，檔案內容與工具不變）：

| 題目 | 定案 | 理由 |
|---|---|---|
| 動畫分鏡 | 只顯示拍、講到、畫面上出現什麼；`#6@儲存` 顯示成「儲存」；「收」那一拍不開放改 | 動態、焦點、音效拍點、插圖元件、位置是給 AI 和 audit 的 |
| 畫面文字 | 只顯示可改的字、中文欄名和字數上限；`cards`、綁句不顯示，存檔時原樣組回去 | 使用者只在意畫面上出現什麼字 |
| 其他欄位 | 「從這句開始」「為什麼這樣做」顯示；截圖觀察等收進「AI 的備註」；插圖清單不顯示 | 預設畫面只留看得懂、用得到的 |
| 順序 | 每一段 → 要決定的事 → 參考資料（全部收起）；只改顯示順序，檔案順序不動 | 照使用者閱讀的順序 |
| 回饋 | 目錄標出有調整的段；想換成可以按「取消」；情境動畫在選單另成一組 | 看得出改了哪裡、改錯能馬上退回 |
