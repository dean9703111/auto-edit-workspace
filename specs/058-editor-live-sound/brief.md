# 058 剪輯台：聲音即時生效、要更新時按鈕發光

2026-11-17，作者開著 PPA 系列六支的剪輯台時說：「我認為『聲音』相關的調整應該要即時渲染，而不是要手動點擊；而瘦身美顏這個部分，如果需要點擊更新才生效，那個按鈕應該要稍微發光讓人知道吧？這樣的 UIUX 體驗應該更好」。

## 現況

- **快速試聽**：聲音滑桿一拖就聽得到（`editor/preview.js`）。
  - 背景音樂（057）的做法：播上一次 build 混好的 wav，只補「現在的值減掉做進去的值」那幾 dB。
- **完成影片預覽**：播的是上一次 build 的 `work/hyperframes/index.html`（`<hyperframes-player>` 的 iframe，同源）。聲音改了要按「更新預覽」重新 build 才聽得到。
  - 下面這幾樣已經是「不用重新產生、直接改 iframe」：主題、字幕樣式、重點字幕、打字時的字卡文字（`PlayerPreview.applyTheme`、`applyCaption`、`applyMarks`，`app.js` 的 2543 行附近）。
- **iframe 裡出聲音的元素**（`projects/ppa-主宣傳片/work/hyperframes/index.html` 看到的）：
  - 人聲：`video#rough`、`#rough-2`…、`#rough-tail`，都有 `data-has-audio="true"`，src 是 `assets/rough.mp4`。人聲音量、範圍音量、拉平都已經做進這個檔。
  - 音效：`audio#sfx-*`，帶 `data-volume`。
  - 背景音樂：`audio#bgm-bed`。
  - 素材原聲：`video#mv-*`，沒開原聲的是 `muted`。
  - 片尾配樂：有配的集數才有，照 build 的實際 id 找。
  - 播放器每一格會把 `el.volume` 設回去（057 done.md），所以從外面改 `volume` 沒用。
- **「更新預覽」按鈕**：預覽不是最新的時候加 `primary`（`app.js` `renderHeader` 的 `needBuild`）。
  - 判斷靠伺服器的 `preview.stale`：plan.json 比 index.html 新就算（`editor.mjs` 612 行）。所以只改了聲音也會叫你按。
  - 按鈕只是換底色，沒有其他提示。作者改瘦臉、美顏時沒注意到要按。

## 要做的（我先定的，作者事後可以推翻）

### 1. 聲音在完成影片預覽也即時生效

**範圍**：
- **一定要做**：
  - 「整支 → 聲音」的人聲、音效、素材原聲、背景音樂四個滑桿。
  - 時間軸軌頭的數字和 🔇（同一個值）。
  - 人聲範圍音量（`edit.gains`）。
- **做得到才做**：
  - 單段音效音量（`sfxVolume`）。
  - 自己加的音效（`edit.sfx` 的 db）。
  - 單段素材原聲（段的 `volume`）。
  - 條件是 iframe 裡的元素對得回那一段。對不回就維持「更新預覽」，寫進 done.md。
- **不在範圍**：
  - 拉平人聲（`edit.level`）：逐句的增益是 build 算的，維持「更新預覽」。
  - 剪段、加刪音效、換曲：要重新排時間，維持「更新預覽」。

**做法**：
- 用 Web Audio 的增益，不改 `el.volume`，所以不會被播放器設回去。
  - 每個出聲元素接一個 `GainNode`，增益＝`dbToGain(現在的值 − 做進去的值)`。
  - 人聲範圍音量照播放頭的 rough 時間算差（`gainAt`）。
  - 🔇＝0。
  - 只有先試做確認不可行，才換別的做法，並寫進 done.md 說明原因。
- **「做進去的值」從哪來**：build 時記下來，比照 057 的 `.cache/bed.json`。
  - 可以擴充成一份記全部聲音的檔；舊的 `bed.json` 讀法要相容或一起換掉。
  - 重新 build 之後差是 0，不會疊兩次。
- **注意的地方**：
  - 播放器重新載入（更新預覽、換專案）之後要重新接。
  - `AudioContext` 被瀏覽器擋（還沒點擊）時不能讓預覽變成沒聲音。接不上就退回原本的做法，並提示「按「更新預覽」才聽得到」。
  - 快速試聽原本的行為不能壞。
- **「預覽不是最新的」要分開算**：
  - build 時另外記一個「plan.json 拿掉上面那些聲音欄位之後」的指紋。
  - `/api/state` 的 `preview` 多給一個欄位，說「跟上次 build 比，只差聲音」。
  - 只差聲音時：
    - 「更新預覽」不發光、不當主要按鈕。
    - 預覽下面那行提示改成類似「聲音已即時套用；輸出時會一起重新混音」。
  - 頁面上還沒存的修改（`isDirty()`）也要分得出「只有聲音」。
- **輸出不能出錯**：
  - 輸出完成影片照樣先 build，`deliver.mjs`、剪輯台的「輸出完成影片」不能因為「只差聲音」就沿用舊的 index.html 或舊的 final.mp4。
  - 寫一個測試，鎖住「只改了聲音 → 輸出的音量是新的值」。

### 2. 要按「更新預覽」才會生效時，按鈕發光

- **什麼時候發光**：還有改了、但完成影片預覽看不到的修改。
  - 包括瘦臉、美顏、瘦小腹、調光、構圖、拉平、剪段、字卡內容等，也就是第 1 點之外的全部。
- **樣子**：
  - 「更新預覽」除了原本的 `primary`，再加一圈柔和的光暈，大約 2 秒一次、慢慢呼吸。
  - `prefers-reduced-motion` 時不動畫，改成固定的光暈外框。
  - 正在更新（「更新中…」）時不發光。
- **「講者」區塊**：瘦臉、美顏、瘦小腹、調光跟上次做進預覽的不一樣時：
  - 滑桿下面出現一行提示，帶一顆小的「更新預覽」按鈕，按下去和右上角那顆做同一件事。這顆也發光。
  - 提示要講「長片要幾分鐘」這類代價（現有 tip 的字可以沿用）。
  - 比對的「上次做進預覽的值」用伺服器已經有的資料（`look` 狀態、build 的快取）。找不到可靠的來源才退回「plan.json 比預覽新」。
- 其他提示文字（tip、`modeNote`）配合改：聲音那幾個滑桿的 tip，不要再寫「完成影片預覽要按『更新預覽』」。
