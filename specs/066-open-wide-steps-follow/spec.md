# 066 橫式錄影段：先全景再推近、步驟跟著操作

直接在主工作區分支 `061-screen-frame` 上改（上面有 061–065 未 commit 的改動），沒有 commit。

## 作者的話

1. 「請檢查全部的螢幕錄影片段，在橫式影片如果使用運鏡技巧，應該要先全畫面，有需要再縮放，這樣比較容易理解（選 Local → Select folder → Add new project，建一個專門給 MiniMax 的空白資料夾）」
2. 「然後如果左邊跟右邊都有步驟，也會讓人產生混亂，這塊請思考如何優化，原則上建議保存右上，左邊的或許是跟著操作移動」

右上＝小節角標（例「STEP 1｜安裝 MiniMax」）；左邊＝錄影段 `steps` 產生的 STEP 膠囊（原本固定在錄影可見區左上）。

## 定案（主代理替作者定的，每一條都可以推翻）

### A. 橫式先全景再推近

| # | 定案 | 可以改成 |
|---|---|---|
| A1 | 只改橫式；直式照舊（`start` 第一格就推在那一塊，`tl.set`）。 | 直式也先全景（直式 16:9 錄影全景只有 1080 寬，第一格上半有黑底，055 C10 才要求直式寫 `start`，所以沒改） |
| A2 | `start` 在橫式：段頭先停全景 **1.2 秒**（`OPEN.hold`），再用一般運鏡的速度推到那一塊：倍率 ≥ 2 用 **2.2 秒**、以下 **1.5 秒**（`MOVE.durBig`／`MOVE.dur`），`power2.inOut`。之後的 `moves` 從那一塊出發。 | hold 改長／短；推的速度另訂 |
| A3 | 開場推近不算進 `moves` 次數上限（報告的「運鏡 N」、`json.view.moves` 也不算）。 | 算進去 |
| A4 | 段起點的硬推 `moves[0]`（≤ 0.3 秒內、`dur` ≤ 0.3，原本叫 `asStart`）在橫式照 `start` 處理（一樣先全景再推），⚠ 改成新說法：`moves[0] 在段起點就推（0.2s）：橫式改成段頭先看全景 1.2 秒、再推到這一塊（和 "start" 一樣）→ 改寫成 "start": [...]、拿掉這個 moves`。直式的 ⚠ 原文不變。 | 硬推照舊（第一格就在那裡） |
| A5 | 推近要在第一個「要鏡頭靜止」的東西開始前結束：`callouts`、`arrows`、`lens`、`spot` 的 `at`、第一個使用者寫的 `moves` 的 `at`。`marks` 不算（紅框在運鏡層裡，跟著推，線寬自動補）。 | 紅框也算（推近期間不出紅框） |
| A6 | 推完要在那一塊停 **≥ 1 秒**（`OPEN.stay`，到第一個 `moves` 或段尾）。這條和 A5 一起當期限：放不下先縮 hold（最少 **0.5** 秒）、再縮推的秒數（最少 **0.8** 秒），還是放不下就**不推**（整段停在全景直到第一個 `moves`，`moves` 改從全景出發），印一條 ⚠。 | 「停 ≥ 1 秒」不縮短，放不下就直接不推；最短值另訂 |
| A7 | 驗證用的 `camAt(t)`、`moving(a, b)` 都含開場推近：紅框被擋／跑出畫面、箭頭、說明卡、放大鏡的位置、隱私沒打碼（C16）、推近切掉整頁（C12，改量推完那一刻）都照新的鏡頭算；紅框線寬在推近期間反向補。 | — |
| A8 | `--check --json`：`annotations.start` 多 `at`（開始推的完成影片秒數）、`dur`；不推時沒有 `start`。報告寫「起始鏡位 2 倍（先看全景 1.2 秒再推近）」。 | — |

不推時的 ⚠（三種，照擋住的是什麼）：

- `start 的開場推近（橫式段頭先看全景 1.2 秒再推近）放不下：callouts[0] 在 0:11.00 就開始（那時畫面要靜止），先停全景 0.5 秒再推 0.8 秒也來不及 → 這段停在全景、不推；要推近就把 callouts[0] 往後挪到 0:11.30 之後`
- `…放不下：moves[0] 在 0:12.00 就開始，先停全景再推完，在那一塊停不到 1 秒 → 這段停在全景到 moves[0]、不推；要推近就把 moves[0] 往後挪到 0:12.30 之後`
- `…放不下：這段只有 2s，先停全景再推完，在那一塊停不到 1 秒（最短要 2.3 秒） → 這段停在全景、不推；要看那一塊就把段拉長，或改用紅框 marks、放大鏡 lens 指出來`

### B. 橫式步驟跟著操作

| # | 定案 | 可以改成 |
|---|---|---|
| B1 | 橫式不再有固定在左上的 STEP 膠囊，右上的小節角標保留。每一步（`steps[i]`）一個步驟標籤（號碼圓點＋文字，沿用膠囊樣式；號碼累加、同字沿用規則不變），貼在「這一步正在操作的東西」旁邊，用錄影座標放、跟著運鏡移動。 | — |
| B2 | 找操作對象：這一步 `at` 到下一步 `at`（或段尾）之間**出現**的（比 `at` 早 **0.5 秒**內出現的也算；前一步就在的不算），在這一步裡至少露 **0.5 秒**；依序 `marks` 紅框 → `arrows`（箭頭和它指的點）→ `callouts` 的框 → `lens` 的框 → 這一步期間推近的 `moves`／`start` 框，同一種取最早出現的。 | 「前一步就在的紅框也算」；順序改 |
| B3 | 貼的位置：對象外側，依序試左上外緣（左緣對齊、底離框 **12 px**）→ 下緣 → 右側（離框 12）；上下兩種左右會挪進可見區、右側上下會挪進可見區。標籤露出的整段期間（含換步淡出的 0.25 秒），在每個運鏡停下來的那一刻都要：在可見區裡（安全區，有錄影畫面框時是框內 inset，∩ 錄影本身）、不壓小節角標、子母畫面、說明卡（框和卡片）、箭頭、放大鏡的鏡片、紅框（外擴 2 px）。 | 加「左側」；聚光燈亮區也避 |
| B4 | 找不到對象、或三邊都放不下：錄影可見區**左下角**（左＝錄影左緣 + 32、不小於 48；底＝錄影下緣 − 32、不大於 900；有錄影畫面框時離框左、下 `inset`），不跟運鏡。左下角的標籤壓到同時出現的說明卡、聚光燈亮區、箭頭、紅框 ⚠。 | 放不下時照舊貼著、只 ⚠ |
| B5 | 進場、換步沿用膠囊的節奏：第一步淡入＋x −24→0 0.5 秒；換步舊的那顆 0.25 秒淡出、新的那顆 0.1 秒後 0.35 秒淡入；同一步跨段接續（carry）直接出現不重播。 | — |
| B6 | 跟著運鏡的做法：標籤位置＝錄影座標的一點（貼著的那個角）在畫面上的位置＋固定位移（字不跟著放大）。運鏡是 x、y、倍率照同一條曲線走，那一點在畫面上也是同一條曲線，所以每個運鏡配一個同時間、同 ease（`power2.inOut`）的 x／y 補間（外層 `.mtag`；淡入淡出做在裡面的 `.msteps`）。圖片慢推（kenburns）也配一個 `ease: 'none'` 的補間。 | 標籤放進運鏡層（會跟著放大） |
| B7 | `stepsSide` 在橫式沒有作用：⚠ `stepsSide 橫式不用寫了：步驟標籤改成貼在這一步操作的東西旁邊（紅框、箭頭、說明卡、放大鏡、推近的框），沒有就放錄影左下角 → 拿掉 stepsSide`（寫錯的值在橫式也只 ⚠，直式照舊 ✖）。 | 欄位直接拿掉 |
| B8 | 原本的膠囊碰撞檢查：`capsuleSide`、`capsuleCollisions`、`badgeCollisions` 裡的膠囊、`placeCallouts`／`mediaArrows` 避開膠囊，在橫式都跳過（膠囊是 `null`）；步驟標籤在說明卡、箭頭擺好之後才放（`placeStepTags`），由標籤去避開它們；左下角的標籤另外查碰撞。 | — |
| B9 | `--check --json` 的 `annotations.steps[i]` 多 `tag: { side, target, box }`：`side`＝`top`／`bottom`／`right`／`corner`，`target`＝`marks[0]` 之類或 `null`，`box`＝露出那一刻的畫面框 x1, y1, x2, y2。 | — |

## 數字

| 項目 | 值 |
|---|---|
| 段頭全景 | 1.2 秒（最少縮到 0.5） |
| 推近秒數 | 倍率 ≥ 2：2.2 秒；以下：1.5 秒（最少縮到 0.8） |
| 推完停在那一塊 | ≥ 1 秒 |
| 最短能推的段 | 0.5＋0.8＋1＝2.3 秒 |
| 標籤離對象 | 12 px |
| 對象要在這一步裡露 | ≥ 0.5 秒（這一步不到 1 秒時取一半） |
| 比這一步早出現也算 | 0.5 秒內 |
| 左下角 | 左：錄影左緣 + 32（≥ 48）；底：錄影下緣 − 32（≤ 900）；有框時離框 inset（預設 24） |
| 標籤大小 | 高 80、寬＝字寬 + 118（和膠囊一樣） |

例（1920×1080 錄影、沒有框、段 10–20 秒）：`start: [480, 270, 960, 540]` → 2 倍，11.2 秒開始推、13.4 秒推完；紅框 `[700, 400, 200, 80]` 和第一步同時出現 → 標籤在 (726, 248)，推近時一起移到 (491, 118)；沒有對象的步驟 → 左下角 (157, 820)。

## 已知限制（作者可以決定要不要補）

- 紅框跟捲動（`path`）時標籤不跟，停在這一步開始那一刻紅框的位置。
- 對象是推近的框（`moves`／`start`）時，推完框塞滿畫面、外側放不下，大多會落到左下角。只有 `start`、沒有紅框的段，第一步通常在左下角。
- 擺位置的檢查用線性內插的鏡頭（和其他檢查一樣），實際畫面是 `power2.inOut`；標籤的補間本身是精確跟著運鏡的。
