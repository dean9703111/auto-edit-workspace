## 共通做法

- **疊加的下方字卡（06–11、14、15）**：卡片撐滿卡片帶，外框寬 880（x 60–940），正文 64 起跳。正文字級照字數算（mustache 的 `*_len`／`*_maxline` 寫進 `@style-portrait` 的 `clamp()`），短句放大、長句縮到下限（52–54）；還放不下才換行。卡高壓在約 250–330，夠高才算填滿（≥ 70%），超過約 330 會報 ⚠ 壓到講者（40%）。
- **兩列卡（09、10、14、15）直式不放標籤**（問答／小技巧／講師／金句）。省下 56 高給兩行內容；Q／A 方標、勾選方塊、姓名板、主色引號已經說明卡片的類型。06、07、08、11 的標籤照舊，字從 56 加大到 60。
- **換行只在詞與詞之間**：P.chars 把字拆成一字一格（inline-block）以後，瀏覽器在任何字之間都能換行，避頭點也失效（實測「Skill：工具附／的使用說明書」）。所以在 timeline 開頭加一段，只在直式時執行（子合成 1080×1920；全幕版看 `P.portrait`），用 `Intl.Segmenter` 照詞包成不斷行的 span：標點和「的了嗎呢吧啊著過」黏在前一個詞，6 字以內的 `**關鍵詞**` 整個不拆，用 `//` 斷開的每一行各自平衡。06 的「名詞：定義」固定在冒號後換行。橫式不執行這段，畫面逐像素不變。
- **全幕版（06、09、11、15）**：寫了 `@style-full-portrait`，字級照畫面上的大小回推（× 0.5952），內容撐滿舞台窗。
- 每一支情境原本那行 `#… { left: 60px; bottom: 680px; }` 都沒改，新的值另起一條規則（`build.test.mjs` 的直式 fixture 用正規表示式比對這一行）。

## 機制缺口

1. **情境沒有直式的上限**：scene.json 的 slots 只有橫式的 `max`／`maxLine`，`resolveScene` 的 view 和 rules 也拿不到版式。所以直式字太長時沒辦法 ⚠，只能在模板裡讓字級照字數縮（下限 48–54）、再不行就換行。建議 scene.json 的 slot 收 `portraitMax`（照 custom-fill 的寫法），或在 rules 的 view 裡放 `format`。有了以後，字級可以改成固定值，長句交給 `--check` ⚠。
2. **疊加情境在直式沒有 `P.portrait`，root 也沒有 `data-format`**：kit 只在舞台縮放（STAGED）時標記。timeline 只好看 root 的 `data-height > data-width` 判斷。建議 kit 對寬 < 高的子合成也設 `P.portrait`。
3. **audit `layout-gap` 誤報置中的 2＋1 換行排法**（`lib/audit-layout.mjs` 的 `colsOf`）：第三塊和第一、第二塊都左右重疊，被串成同一欄，同一列的兩塊算出負間距。建議分欄時，上下重疊（同一列）的不併成一欄。
4. **P.chars 拆字以後，在任何字之間都能換行，避頭點也失效**：六支模板（06、08、09、10、11、15）各自貼了一份「照詞包 span」的程式，09 全幕版另有一份簡化版。建議收進 kit，例如 `P.chars(sel, at, { words: true })` 或 `SceneMotion.words(el)`，只在直式做。另外 ICU 的分詞偶爾斷得不理想，例：「沒／問題」。
5. 標準之間會互相擠壓：「卡片帶高 ≥ 70%」（252）和 audit「蓋到講者框 ≥ 40% ⚠」（卡高約 330 以上）之間只剩約 80 px 可用。兩列卡不放標籤就是為了待在這個範圍裡。要放寬的話，得改 `SPEAKER_WARN_TEMPLATE`，或直式的卡片帶高度。
6. 橫式的畫面沒變，可是 06、08、09、10、11、15 的 timeline 多了只在直式執行的程式，所以橫式子合成的內容（hash）變了。現有橫式專案下次 build 會重產這幾段，畫面一樣。盤點提到的 07 橫式半像素邊沒修，因為這次規定橫式不能變。
