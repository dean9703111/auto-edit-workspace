## 共通做法

- 寫法照 0.md：
  - CSS 用 `#x-名[data-format="portrait"]`，寫在每支最後一條橫式規則後面，加 `/* 直式（056）…*/` 註解。
  - 換排法用 `data-*-portrait`。
  - script 分支用 `P.portrait`。
  - 每支檔頭【版面】最後都加了「直式：」那幾行。
- 標題列字 64 → 76（54 → 64），主要字一律 72（61）。
- 放不下時不縮主要字，改成換排法，或用 `portraitMax` 減字數。
- 站數判斷不寫 `#…-n4`。4 站寫 `:has(> .x-node ~ .x-node ~ .x-node ~ .x-node)`，第 3、4 站寫 `.x-node:nth-of-type(3/4)`。填 3 站時第 4 站的 id 才會整組拿掉（custom-fill 測試會查）。

## 機制缺口（沒改共用檔，都在模板裡繞過去或留 ⚠）

1. **audit 的 portrait-cam 不看元素看不看得到**：它把 P.cam 容器底下所有絕對定位的 [id] 子元素都算進去。
   - 在 x-prompt-tree，送出後鏡頭會往下帶，讓膠囊和根節點在正中。那時章節卡還沒彈出（opacity 0），但 audit 還是報「下緣會切掉 204px」。
   - 不帶的話，這幾秒內容都擠在上面，會改報 vbalance，所以選擇留這個誤報。
   - 建議：只算那個時刻看得到的元素，或在每個 P.cam 終點照當時的可見度量。
2. **audit 的 layout-gap 會把 free 版面裡不是同一欄的東西串成一欄**：它照錨點重疊來分欄。
   - x-process-loop：四角的站加上正中的主題，被當成一欄。
   - x-architecture：雲端、結論、裝置三層，被當成一欄。
   - 兩支都報出 -146、-152 這種負的間距。也沒有屬性可以讓這條豁免。
   - 建議：間距是負的（兩個元件在另一軸上互相錯開）時不要串成同一欄，或加一個類似 `data-layout-gap-ignore` 的豁免屬性。
3. **SceneLayout 的 linkPts 只要兩個框在 x 上有一點重疊，就畫垂直直線**：x-architecture 直式的裝置變寬後，經雲端的線會直直穿過結論卡（audit 報 layout-link ×2）。我在模板 script 裡重算了 L 形路徑。
   - 建議：直線會穿過別的元件時改走 L 形，或讓 data-links 可以指定走法。
4. **compare.mjs 只測完整的 sample**：3 站、2 項、最長字這些變體沒有被涵蓋到，這次是我手動複製專案測的。
   - 建議：加一個 `--variants`，至少跑 sampleMin 和每個 `@sub n==` 分支。
   - 另外，compare 改後的 `ink`（內容外框）有量，但沒有寫進 report.json，所以內容占比只能另外從截圖量。
