# 工程師下班有約：剪輯風格規範

這份文件是給 AI 看的剪輯規則。規劃動畫、上字幕、挑音效時，一律以這份為準。

## 畫布

- 1920×1080、30fps（直式 1080×1920，見「直式」）
- 講者固定機位，位置以專案資料夾裡的場地照為準（每集 `qc.mjs speaker` 會產生 `work/場地照-動作範圍.jpg`）
- 構圖：四周有多餘外框（黑邊、櫃子、大片空牆）時先放大裁切，讓講者成為畫面主體；倍率以不切到手勢、畫質不明顯變軟為限（原片 640×360 這類低解析度建議 ≤ 1.15）。每集做出完成影片前先開構圖台給作者拖框（`qc.mjs framing` 算建議的框）

## 講者畫面（調光、瘦臉、美顏）

- 預設：**不調光、不瘦臉**（`kit/look.json` 兩個都是 0），使用者在構圖台（停點 ②）和構圖一起決定，或之後在剪輯台「講者」、用說的開。要開時建議調光 **0.8**（＝剪映「智能調色」80，含美白 30）、瘦臉 **0.6**（＝剪映「瘦臉」60＋「V 臉」10）。只開這一集寫 plan.json 的 `look`；以後每集都要，才改 `shared/template/kit/look.json`
- 範圍：調光 0–1（0＝不調）；瘦臉 0–1.2（0＝不瘦；超過 1.2 脖子、領口會被拉彎）；美顏 0–1（0＝不做；要開建議 **0.5**）
- 調光是一支固定的 3D LUT，從作者在同一個場地、同一台相機的剪映完成影片擬合出來（esim_ep2 第 8–16 秒），和剪映的色差平均 3.5（背景）／4.4（臉）ΔE；剪映會依每支影片自動分析，這裡不會。換場地、逆光、戶外時先看 `work/look-preview.jpg`，太過就調低或關掉
- 瘦臉只動臉頰到下巴的輪廓，不動眼睛、鼻子、嘴；每一格跟著臉走。側臉時自動減半，偵測不到臉的格自動淡掉
- 臉在畫面裡太小（臉寬 < 60 px）就不瘦臉，只調光
- 美顏（`look.beauty`）＝磨皮＋膚色提亮＋淡化黑眼圈：只動臉型輪廓裡的皮膚，眼睛、眉毛、嘴巴扣掉，邊緣羽化；磨皮保邊（眼鏡框、五官輪廓、髮絲不糊），眼下提亮並把偏紫的色偏拉回中性。和瘦臉共用臉部偵測與 `work/rough-look.mp4`，改了強度要重跑 `look.mjs run`
- 不做：大眼、祛斑、法令紋、唇色、腮紅（大眼容易變形，唇色、腮紅要使用者要求才加）

## 講者

14 講者介紹字卡的姓名、頭銜（和 15 金句的出處）放在 `shared/setting.json`：每個人本機各一份、不進版控，更新工作區不會被蓋掉。範本是 `shared/setting.example.json`（示範人物林大寶）。

- 設定：`node shared/template/tools/brand.mjs speaker --name "<姓名>" --titles "<頭銜1>,<頭銜2>"`（姓名最多 5 字；頭銜 1–3 個，每個最多 6 字；`--short` 是金句出處，不給＝姓名）
- 不放講者介紹：`node shared/template/tools/brand.mjs speaker off`
- 還沒設定時，講者介紹會顯示示範人物林大寶，`status.mjs` 與 `build.mjs --check` 會提醒

## 字幕

- 字型：英文與數字用 **Google Sans Flex**，中文用 **Noto Sans TC**（＝剪映的思源黑體 TW）
  - Google Sans Flex 沒有中文字，一定要搭配中文字型，不能只指定它
  - 兩套都是 Google Fonts 上的開源字型（SIL Open Font License）
- 字色：白色，無描邊、無陰影
- 底板：黑色，不透明度 70%，直角（不要圓角），寬度貼合文字（不要整條橫幅）
- 尺寸：字級 **76 px**（畫面高的 7%，＝剪映字號 7）、字重 **400**（Regular）、底板高 **118 px**（內距上下 **24 px**、左右 **37 px**）
- 字間距：0（剪映沒有加字距）
- 位置：水平置中，底板下緣距畫面底 **6 px**（底板在 y 956–1074，字幕區裡）
- 一則＝一個完整語句：有 `講稿.md` 時每則就是講稿的一行（講稿是一句一行的提詞稿）；沒有講稿時照語音的句子切成完整子句。不斷在詞語中間，連接詞不吊在句尾
- 每則最多 18 個字（估寬上限 1840 px；直式 10 字，見「直式」），只排一行；超過才拆成兩則（先斷在「、，」，沒有標點斷在停頓最長的地方）；同一口氣的短行併成一則（四條合併條件與連接詞清單見 `auto-edit-rough`「判準與數字」）
- 剪映的長相：平均約 12 字、2.3 秒一則，最短 0.6 秒；字幕首尾相接，相鄰空檔不到 1 秒不留白
- 標點：顯示時去掉「，」「。」「；」「：」，保留「、」「！」「？」（列舉與語氣）
- 字幕由 `node shared/template/tools/media.mjs srt-align --project projects/<專案>` 產生（剪乾淨第 6 步：時間由詞級逐字稿對齊，不用自己拆句、對時間）；plan.json 寫好之後要拆，到剪輯台分割（剪輯台會一起重對句號）
- 同一時間只顯示一則字幕
- 技術名詞保留英文原文，中英文之間加半形空格（例：用 MiniMax Code 剪片）
- 實作在 `shared/template/kit/captions.css`，由 `build.mjs` 套用

## 直式

版式在開工決定一次（`auto-edit-longform`「版式」），plan.json 第一層寫 `"format": "portrait"`。下面的數字只寫在這裡和 `shared/template/tools/lib/canvas.mjs`（`CANVAS.portrait`），兩邊要一致。

- 畫布：1080×1920、30fps
- 不安全區（平台按鈕、標題會蓋住）：頂部 y 0–240、底部 y 1440–1920、右側按鈕列 x 940–1080 × y 840–1440
- 文字安全區：y 240–1440；y 840 以下右緣 940（右側按鈕列）；左右各留 60 px
- 版面只有三種：疊加（講者滿版、卡片在卡片帶）、上下分割（取代子母畫面：分割線 y 900，上半 1080×900 資訊、下半 1080×1020 講者）、全幕；03 半版側邊欄、05 兩側不提供
- 上下分割的資訊窗：x 40–1040、y 240–876；04 家族與情境動畫的 1920×1080 子合成整張等比縮 0.8475 放進來（不用改檔），所以內容一樣只排在 x 120–1300、y 130–880
- 卡片帶（下方字卡、11 總結、15 金句）：x 60–940、y 880–1240，不擋臉
- 章節角標：左上 x 60–684、y 250–362（右上是平台按鈕列）
- 字幕：字級、字重、底板、內距和橫式同一套（本檔「字幕」）；每則最多 **10** 個字（置中後底板不壓到右側按鈕列）；字幕帶 y 1280–1420（講者胸前，底部按鈕列之上）
- 構圖：講者頭頂落在 y 380–520、下巴 ≤ 860（停點 ② 的預覽一起看）
- 文字最小 32 px（輸出像素；audit ⚠ `font`）。縮放進上半面板的段看「字級 × 縮放倍率」，所以寫字級的下限是：全畫面 custom 與 04 家族 ≥ 38 px（縮 0.8475）、01 章節 ≥ 52 px（縮 0.625）、字卡動態（fx）的大字 ≥ 57 px（縮 0.5625）；不縮放的段（疊加、上下分割的下方字卡）字級 ≥ 32 px
- 縮放的段裡帶 id 的元素擺位超出舞台窗 x 120–1300、y 130–880（01 是 x 160–1760、y 260–870）會被切到：audit ✖ `portrait-window`，把元素移回窗裡
- 鏡頭推（`P.cam`）推近後，內容外框要留在子合成座標 x 72.8–1347.1、y 130–908.8 裡（容許 2 px）：超出是 audit ⚠ `portrait-cam` → 內容群縮小一級（`data-gap` 改小一級，或字級 −4），或這段不用 `P.cam`
- 字卡動態（fx）在直式縮 0.5625 倍放中間：`shared/template/fx/catalog.json` 標 `"portrait": "band"` 的 14 張（07、09–18、21、31、33）只剩中間一條，`--check` 會 ⚠ → 換 `"portrait": "ok"` 的特效或拿掉；挑特效先打開 `shared/template/fx/index.html` 按「直式預覽」看
- 錄影段：16:9 錄影在直式只有 1080 寬，一定要用 `moves` 推近到操作區；手機直式錄影鋪滿（`"pip": false`＋`fit: "cover"`）

## 動畫視覺

- 顏色以 `shared/template/kit/brand.css` 為準（主色橘 #F6630F；全畫面與側邊欄是淺暖底 #FFF8F3＋白卡黑字，下方字卡是近黑 #141414＋暖深灰錯位底板，橘色標籤白字）；背景圖每種版面一張（`bg-fs.jpg`、`bg-side.jpg`、`bg-ch.jpg`）；字卡與模板動畫從 `shared/template/` 情境庫挑，內容設計動畫照內容設計（見「內容設計動畫」），規格見 `shared/template/USAGE.md`
- 主題：亮、暗兩套（plan.json 第一層 `"theme": "light"`＝預設、`"dark"`），只換顏色 token，版面與動態共用
- 風格看底：**疊在實拍上**（疊加版面的卡片）永遠硬邊——實心錯位底板＋一層淡落影（模糊 ≤ 30 px、不透明度 ≤ 0.35），不發光、不漸層；**不透明幕上**（全畫面主卡、側邊欄面板、全幕）才可以有柔影、光暈、漸層，而且只能用 `--v2-*` token，不寫死顏色與陰影
- 主色只給焦點（講到的那一站、重點條、數字）；標籤、還沒講到的圖示用墨色
- 動態的單位是「拍」：每個綁句點（`P.at`）是一拍＝進場 → 強調 → 其他元素退焦 → 一顆音效；同一時間只有一個焦點。拍與拍之間停在完成態，不加微動（使用者：「我不需要這些畫面的微動」）：背景不疊光暈、浮塵，圖示與數字不呼吸，虛線不流動，卡片和焦點落定後不漂浮；底版（主卡、視窗、背景）不縮放不移動，`P.cam` 指到有底的容器不推。動作名稱只用 `shared/template/BEATS.md` 的語彙表
- 圖示先行：情境有圖示欄位就配圖示，同一個物件全集用同一個圖示；清單的圖示要配就每一項都配，不要只配一部分
- 圖示是「描出來」的：容器先進場，0.15 秒後把線描出來（0.7 秒，模板自動做）；總結、回顧用圓環＋打勾；流程圖的站不打勾，講到的站「聚焦」（放大、亮框），走過的站留細框
- 劃掉：人的建議、舊習慣、舊做法用波浪線（`P.strike(sel, at, { wave: true })`，像手寫）；數字、價格、清單上的單項用直線（`P.strike`）
- 蓋章（`P.stamp`）是「判決」：一句話給前面講的東西下結論（過時、已取消、已送出、千真萬確），印章 2–4 字、紅框、略斜，疊在被蓋的東西右下角，被蓋的東西同時退焦；一段最多 **1** 個，配 `impact`；一般重點句不蓋章（用 07 重點字卡）
- 不可擋到講者的臉和手勢，安全範圍以場地照判斷
- 不可壓到字幕區（畫面底部 160px）

## 節奏

- 版面不要一直切（有講者的橫式；工具排好、也會檢查）：開頭 30 秒以字卡為主（講者滿版露臉，卡疊在講者上），讓觀眾先認識講者；半螢幕一次連續 ≥ 15 秒；子母畫面一次連續 ≥ 45 秒（中間的重點、轉場併進前一段，不切回講者）。`build.mjs --map` 會把每一行排進「字卡／半螢幕／子母畫面」的區塊，`--outline` 不合就 ✖，`--check` 印「版面節奏」⚠
- 講者位置：`--check` 印「講者位置：左／中／右」。講者在左時下方字卡靠右、半螢幕的面板從右邊推入；在右時講者只移到右半的中間；透明的字卡動態縮小放在講者旁邊的空位（講者在中間就放在下方字卡的位置），不蓋到臉。要寫死就在 plan.json 第一層寫 `"speakerSide": "left"`（`center`、`right`）。字卡、疊加的模板蓋到臉的位置 ≥ 5% 是 ✖
- 連續覆蓋：從頭到尾每一段講解都有畫面——情境動畫、資訊卡或字卡動態，段與段直接接上，不留沒有畫面的空白
- build 預設照「連續覆蓋」檢查（plan.json 的 `rhythm` 不寫＝`"continuous"`）：`--check` 會列出「沒有畫面的區間」（超過 1 秒），兩段之間只空 1 秒以內會提醒「講者會閃一下」，要改成 0 秒相接；只有這一集要留露臉空檔時才寫 `"rhythm": "spaced"`
- 章節轉場：影片不到 180 秒（3 分鐘）不用；業配段不放；影片第一句就是章節開頭（`## 開場`）也不放，勾子先上，章號從下一章算起。該章第一句前面保留 3 秒停頓（剪乾淨的 `ng-snap` 會保留），章節幕 2.5 秒放在停頓裡，不壓人聲；章節期間不放字幕；前一段的畫面停在完成態，墊在章節底下淡入；一定寫副標 `slots.sub`（≤ 12 字，講這一章要做什麼；講稿 `##` 章名冒號後面那句可以直接用），只有章號和章名（例「結語」）畫面很空，`--check` ⚠
  - 沒有 01 的短片（章節由 02 起頭）：build 在章節起點自動讓主色色帶掃過一次（0.62 秒，不蓋住講者、不用停頓），角標同時擦開；章節起點被全畫面蓋住、或在片頭 1 秒內就不掃
- 小節角標：講稿有 `###` 小節時（plan.json 第一層 `sections`），右上角角標改成「章號＋目前小節」的膠囊（高 80、y 56–136，在全幕卡片頂之上；小節名 40 px、號碼板 64），寬度跟著當下的小節名，講到小節第一句就擦掉舊的、擦開新的；子母畫面、全幕、錄影段都露出（橫式錄影段：錄影旁邊放得下就放在空白處、不壓錄影，放不下就貼著錄影畫面的右上角、離右／上緣 16；STEP 膠囊的字和小節名重複時不畫、⚠ 請刪掉；說明卡與箭頭避開它，紅框被它蓋到 ⚠；直式的錄影段角標和 STEP 膠囊同在左上，由膠囊接手）；名稱最多 12 字（全形 1、半形 0.5；字太多會蓋到畫面）
- 進場時機：段在講到這個重點的那一則字幕開始時進場；卡片主文字、每條項目、每個動畫站，出現時間＝講到那個詞的時間（`#N@詞`，差 ≤ 0.5 秒）
  - `#N@詞` 的秒數由 build 從詞級逐字稿算：你只寫那句字幕裡連續的 2–4 個字，不要自己查逐字稿、不要猜秒數
- 條列進場：每條綁講到它的那個詞（`#N@詞`）逐條進場；沒有句子可綁時每條相隔 ≥ 0.15 秒錯開；絕不整組同時出現
- 情境動畫與條列：任何 1 秒內新出現的元素 ≤ 2 個；同一組依序出現時間隔 ≥ 0.12 秒（這是 audit 報 ⚠ 的門檻；自己排的時候用上一條的 0.15 秒）。亮框、同位置換內容、跟著卡片一起出現的子元素不算新元素；逐字出現的一串字、同一個動作一起錯拍出現的一組，各算 1 個
- 一拍一個焦點：相鄰兩個綁句拍至少差 2.5 秒（太近就綁後面一句，或拆段）；最後一拍之後回均衡（全部亮回、鏡頭回正）
- 吸睛的模板動畫一集有上限：`x-wordcut`（同字異材快切）最多 1 次，用在全片最想讓觀眾記住的那個詞；`x-wall`（情緒詞整面牆）最多 2 次；`x-magazine`（雜誌封面）、`x-breakout`（破框而出）各最多 1 次；超過 build 會 ⚠
- 講者站在動畫前面的模板（`x-wall`、`x-magazine`、`x-breakout`）：build 會把那一段的講者去背、疊在動畫上面，只能用在講者露臉的段。第一次用要下載去背模型（約 170 MB），build 印 `✖ … 去背模型還沒下載` 時先問使用者，同意才跑它說的那條指令
- 停留時間：一般卡 2.5–4 秒；07 重點字卡（不論 tone）停到這個重點講完，至少 4 秒
- 換卡：前後兩張接得很近時，上一張退場和下一張進場同時進行，不要等上一張完全消失才開始
- 動作秒數（kit 常數，模板與情境動畫範例已經內建，不用自己填）：進場 0.5 秒（卡片外殼 0.55–0.8 秒）、強調 0.2 秒、退場 0.28–0.3 秒（比進場快）、鏡頭與容器移動 0.9–1.1 秒；逐字間隔：標題 0.03 秒、重點 0.035 秒、說明 0.045 秒；一組卡或站錯拍 0.12 秒
- 曲線：進場 `expo.out`（擦開、上浮、長出）；強調 `back.out`（彈出、逐字彈出、落地，過衝只用在強調拍）；移動 `power3.inOut`（鏡頭、進度、子母畫面飛入、焦點切換）；轉場 `expo.inOut`（色帶擦開）；退場 `power2.in`；微動用正弦
- 不做微動：只有「等待中」的狀態（例對話的打字小點）可以呼吸，不配音效；卡片、焦點、字、背景都不動
- 一拍裡的先後（T＝綁句點）：T 前 0.5 秒進度與鏡頭出發 → T 元素彈起＋音效 → T 後 0.14 秒說明逐字 → T 後 0.6 秒焦點抬起、上一個退焦
- 完成態停留：新訊息（QA 的答案、Step 2、條列下一條）出現完成後至少停 1.2 秒；段尾最後一幕至少停 1.5 秒才退場；中間的過渡步驟可以只停 0.6 秒

## 分章

- 分鏡一份派一個子代理（`build.mjs --scaffold` 切）：有 `##` 照章切；一份超過 1,000 字（去標點、空白，約 13 段畫面）就切成差不多大的幾份，切點先挑 `###` 小節開頭，再挑剪乾淨時剪過停頓的地方（不會切在一句話中間）；不到 300 字的份併到相鄰那份，併完不超過 1,300 字（作者 2026-11-11：「把每份切小，比較弱的模型也要有一定的水準」；mmx 實測 868 字的一份 3 次都填完，1,956 字的一份 15 次只填完 1 次。原本是 2,000 字）。照字數不照秒數：子代理要讀懂的是字
- 語意地圖一行大約就是一段畫面：超過 10 句或 30 秒 `--map` 會 ⚠ 要拆；A 超過一份行數的 40% 也 ⚠（2026-11-10 MiniMax 試跑：一行塞 10–28 句，草稿只剩 9 段）
- 先畫語意地圖再寫草稿：第一回合每份標語意（`SITUATIONS.md`「語意類型」）和分級，A 亮點（內容設計動畫候選，全片由主代理挑）、B 結構（照語意套模板或錄影）、C 串場（最便宜的畫面，照樣不留空白）；第二回合照地圖挑模板、填字

## 內容設計動畫

- 模板是快速選項，**最能提升質感的是針對內容設計的動畫**（使用者：「不是要你設計時直接參考模板，而是真的根據內容設計」）。套模板省下的時間都花在這裡
- 什麼時候：親身經驗或小故事、比喻、因果與轉折（以前怎樣、後來發現）、抽象的道理、情緒高點、這集最想讓人記住的畫面。判斷方式：把字幕遮起來只看畫面，能不能看懂在講什麼；模板做不到就設計
- 數量：約三成的段標候選（其他七成套模板，相鄰兩段不要用同一個模板）；語意地圖的 A 照這個預算全片挑（`--map-merge` 照地圖行數算），沒有地圖的舊流程 `--check-draft` 照實際段數算，media、章節段不算。段長至少 6 秒、講了 2 句以上才放得下
- 時間（建議初值，2026-11-08 MiniMax 紀錄扣掉白做的時間）：一段約 12 分鐘（鏡位腳本＋動畫）、同時 4 段；停點 ③ 的候選預設都不勾：分鏡確認後先全部套模板合成，看完完成影片預覽不滿意的段再專門設計（說「<段> 重新設計」）；想一開始就做的段在分鏡表勾起來，表下寫全勾要多久
- 做法：草稿先套模板、標成候選，使用者在停點 ③ 勾了、或看完預覽說要重新設計才做；設計師先寫鏡位腳本（這段真正要傳達什麼、用什麼畫面、每句話對應什麼），再從空白畫布做。不參考、不複製模板的畫面；相鄰的設計動畫不要用同一種畫面
- 只是在條列、走流程的段落用模板，不要為了設計而設計

## 情境動畫優先

- 講解在講一個情境時（過程、前後對比、數值變化、比喻、因果、沒有錄影的介面操作），做情境動畫，不要只下一張字卡
- 同時符合三條才做情境動畫，不符合就用字卡（建議初值）：
  - 講解屬於 `shared/template/SITUATIONS.md` 標「情境動畫」的情境
  - 段長 ≥ 4 秒
  - 同一個情境講了 ≥ 2 句字幕
- 字卡留給一個名詞、一句重點、一個提醒
- 畫面主角是圖，字只當標籤（2026-11-03 作者：只有字像在唸講義）：全幕情境動畫每個畫面至少一個插圖元件（`shared/template/kit/illus-gallery.jpg`）或大圖示當主體，項目之間的關係用位置、引線、箭頭畫出來（誰連到誰、從哪到哪、誰包含誰、前後怎麼變）。一列一列「小圖示＋一行字」的清單只用在疊加字卡（12、13）；同一個主體（App、裝置、工具）的 2–4 個功能、特色、毛病用 `x-callout`，主體畫成插圖元件放中間，標籤用引線接到它
- 挑法與範例見 `shared/template/SITUATIONS.md` §3
- 段與段直接接上，不用留露臉空檔；講者露臉靠「疊加」版面（講者滿版、卡片疊在上面）與子母畫面小視窗

## 版面

位置不自己敲數字：元件外層寫 `data-layout` 宣告排法，`shared/template/kit/scene-layout.js` 算位置（群組起點貼齊 8 的倍數），audit 量對齊、等距、內距。

| token | 值（px） | 用在 |
|---|---|---|
| `--sc-grid` | 8 | 所有位置、尺寸、間距都是 8 的倍數（自動貼齊） |
| `--sc-pad-card` | 48 | 卡片內容區左右內距 |
| `--sc-pad-card-y` | 40 | 卡片內容區上下內距 |
| `--sc-gap-xxl` | 160 | 一對元件要拉開（分歧、對照、比喻的兩邊） |
| `--sc-gap-xl` | 96 | 站與站之間（中間放連接線） |
| `--sc-gap-lg` | 48 | 兩欄之間、群組之間、列與列之間 |
| `--sc-gap-md` | 24 | 同一群裡的元件之間、序號圓到文字 |
| `--sc-gap-sm` | 16 | 插圖到它的標籤、圖示到文字 |
| `--sc-link-gap` | 12 | 連接線端點離元件外框 |
| `--sc-link-head` | 16 | 箭頭頭長 |

怎麼宣告（參與排版的元件加 `data-slot`，沒加的不動）：
- `data-layout="row"`：同一列等距、整列水平置中；對齊預設是底對齊（有標籤的，標籤在同一條線；沒標籤、一樣高的，中線對齊），要插圖中線對齊寫 `data-align="middle"`
- `data-layout="col"`：上下等距、中線對齊；`cols-2`：兩欄等寬；`grid-2x2`：四格等寬等高；`free`：不自動排（見下面）
- `data-gap="xxl"`／`xl`／`lg`／`md`／`sm` 選上表的間距；`none`＝貼在一起（人站在桌子後面這種疊在一起的）
- `data-justify="start"`／`center`（預設）／`end`：橫向靠哪邊；`start` 時整群靠左、左內距 48 px（`end` 靠右同理），`col` 裡的元件左（右）邊對齊
- `data-align="top"`：整群靠上（預設上下置中）；`data-row="2"`：放到第二列（列與列之間 `--sc-gap-lg`）
- 連接線寫在 svg 的 `data-links="a>b b>c"`（有箭頭）或 `"a-b"`（沒箭頭）：線畫在兩個元件外框邊的中點之間；同列畫水平線、同欄畫垂直線（直線畫在兩個插圖高度（寬度）重疊段的正中）、不同列欄畫 L 形；線的 id 是 `<a>-<b>`，動畫用這個 id 描線；有箭頭時箭頭頭是另一條 `<a>-<b>-head`，描到箭尖時自動淡入，不用另外寫
- 刻意橫過元件的線（例：時間軸的主軸）加 `data-layout-ignore`，audit 不把它當連接線量
- 會放大的元件（聚焦、過衝）排版時已經照放大 1.1 倍預留，不用自己加距離
- 分鏡表「位置」欄寫排法，不寫像素：`<區域>｜<排法> <第幾個>`，例 `panelTop｜row 1／3`、`panelTop｜row2 1／1`、`panelTop｜cols-2 左`、`band｜free`（`shared/template/BEATS.md` §5）。內容設計動畫（`design: true`）的鏡位腳本照 `auto-edit-motion` 的 `references/design.md` 寫，不套這條

七條規則（audit 會量；印 ⚠／✖ 時照它的改法改）：

1. 同一列的元件對齊（差 4 px 以上 ⚠、16 px 以上 ✖）：放進同一個 `data-layout="row"`，不要手寫 `top`
2. 同一列（欄）相鄰元件的間距一樣大（最大差 ≤ 8 px）：用 `data-layout` 排，不要手寫 `left`
3. 內容群在內容區置中（左右留白差 ≤ 16 px；上下置中時上下留白差 ≤ 24 px）：故意靠上就寫 `data-align="top"`；靠左寫 `data-justify="start"`（左內距 48 px，差 8 px 以內）
4. 內容群離卡片內容區的邊：左右至少 40 px、上下至少 32 px（排版預設 48／40）；放不下就縮小或減少元件，不要貼邊
5. 標籤對它的插圖置中（中心差 ≤ 4 px；標籤在右邊的量上下）：標籤放在元件自己那一格裡，不要另外定位
6. 同一列的標籤在同一條線上（上下差 ≤ 4 px）：用 `data-layout="row"` 預設的底對齊，不要手寫 `top`
7. 連接線端點離元件外框 4–32 px、落在外框邊中點 ±8 px、不穿過別的元件：連接線用 `data-links` 產生，不要手寫 path

什麼時候寫 `data-layout="free"`：位置本身有意思、不是排成列或欄的（地圖上的點、一個元件疊在另一個上面），或沿用還沒改的舊檔。free 只代表排版程式不排位置，上面七條 audit 照樣量（手寫的連接線也量）；量出 ⚠ 要在回報寫為什麼留著。排版程式做不到、那部分可以手寫的三種：一個元件分出 2 條以上的曲線（像分歧）由那支動畫在 script 算，端點用 `SceneLayout.box` 取、不寫死座標；要先往下再橫走的 L 形，拆成兩條或手寫；靠左的欄要每格等寬，先在 CSS 給同一個寬度（audit 照樣量）。示意動畫裡用 `move` 走位的元件（人走到手機旁邊）照樣放在 `data-layout` 裡：等距、置中量它排版時的原位置。

### 全寬（沒有講者的段）

同一支片可以只有開頭結尾露臉，中間全是螢幕錄影、圖片和動畫（中間放 `assets/voice/` 的旁白，或邊錄邊講的螢幕錄影）。這些段沒有講者小視窗，右邊不留給小視窗：04 家族與全畫面情境動畫整段沒有小視窗時，build 自動換成全寬版型（`--check` 那一段寫「全寬版型」；情境庫 ① 版面「全寬」四張示意）。

全寬段要和縮到 87% 的螢幕錄影接得起來（16:9 的錄影放進 1920×940：x 125–1796、y 0–940）：

- **左右對齊錄影**：主卡與內容設計動畫的內容用 x 120–1800，接到錄影時內容邊界不會跳
- **字幕**：y ≥ 920 不能碰，和錄影段一樣
- **右上角**：小節角標放在和錄影段同一個位置（貼著錄影畫面右上角，右緣 1780、y 16–96；有錄影時照片中最長的那支算），錄影和動畫接來接去角標不會滑動。內容要避開它，壓到是 ✖
- **背景**：只留底色，不放 `bg-fs.jpg`。那張圖右上角有裝飾，是給「左邊主卡、右邊留白」的版面用的，內容用滿畫面時會打架
- **內容設計動畫**：內容用滿 x 120–1800、y 40–900；還擠在一邊（中心離中線超過 160）或太小（寬度不到 1100）audit 會 ⚠

| 項目 | 子母畫面 | 全寬 |
|---|---|---|
| 主卡 | 左 120、寬 1180（右緣 1300） | 左 120、寬 1680（右緣 1800） |
| 內容區 | 1176×580 | 1676×580（有 `data-layout` 的照新寬度重排，`row` 站距 96 → 160） |
| 清單（04a） | 只有清單 | 左邊清單、右邊主視覺：`slots.visual` 寫畫廊插圖元件（例 `laptop`），講到每一項重拍一下；沒寫 `--check` ⚠ |
| 寫死座標的內容（`free`）、介面模擬視窗 | — | 寬度不變，整塊置中 |

做情境動畫時，`--check` 寫「全寬版型」的段照 1676 寬設計：插圖放大、多一站、站距用 `xxl`；清單型的左邊放清單、右邊放一張跟著講解動的主視覺插圖，不要讓卡片右半邊空著。

## 示意動畫

- 講解在描述具體的動作、物件或過程（手機、電腦、雲端、人走動、時間流逝）時，用示意動畫：主角是線條插圖，不是卡片上的字（`shared/template/SITUATIONS.md` §3「示意動畫」列）
- 插圖照這個順序找：畫廊裡有的元件（`shared/template/kit/illus-gallery.jpg`）→ lucide 圖示（模板 `x-scene` 的 parts 寫 `icon`，名稱用 `build.mjs --icons 甲,乙` 查）。模板段不新畫 SVG。內容設計動畫：簡單的形狀和線（卡片、格子、條、連接線）設計師直接用 HTML、CSS、inline SVG 畫；有外形的物件先用現成的（線稿元件庫、圖示、registry），都沒有合用的才新畫，照 `shared/template/kit/illus-style.md`、過 `media.mjs illus-lint` 才用，一段最多新畫一個，要和現成元件看起來是同一套（線粗、圓角、用色）。現成的元件只是資源，不限定題材（`auto-edit-motion` 的 `references/design.md`、`design-kit.md`）
- 相片、背景、質感圖不放進示意動畫；示意插圖一律是向量線條
- 貼紙風格（選用）：`x-scene` 的 slots 第一層寫 `"sticker": true`，元件變成有白邊和落影的貼紙、一張一張貼上（不用畫的），最後一拍可以寫 `{ "at": "#N@詞", "peel": true }` 整組撕走。用在「要準備這幾樣東西」「這些以後都不用了」這種列舉後收掉的句子；一集最多 2 段
- 字只當標籤：寫在元件旁邊，每個 ≤ 10 字；完整句子交給字幕
- 內容設計動畫的大小（觀眾多半用手機看）：主角（這一拍在講的那個物件）長邊 300–480px，畫面只有一兩個物件時到 560px；配角長邊 ≥ 180px；標籤字 36–44px，重點數字或關鍵詞 ≥ 72px，圖示圓 ≥ 96px。畫廊元件的尺寸是長寬比和下限，照比例放大。audit 量完成態：內容蓋到的面積不到主內容區 30% 報「畫面太空」（自己畫的圖形也量）；用了線稿元件時，最大的那個長邊不到 300px 報「主角太小」；顏色寫了色碼（沒用 token）報「顏色寫死」；轉了非 90 度的角度報「旋轉了非 90 度的角度」
- 模板段 `x-scene` 照 `build.mjs --spec x-scene` 填 parts 和 beats，挑元件和拍看 `shared/template/BEATS.md` §5.4 那張表，不寫動畫分鏡、插圖清單；內容設計動畫的鏡位腳本照 `auto-edit-motion`。版面、動態、節奏照本檔「動畫視覺」「節奏」

硬規則（audit 量不到，做完對著截圖一條一條看）：

1. 強調靠框色、字色，不要用亮色大面積填滿元件；疊在實拍上的元素照「動畫視覺」用實心底（亮色底輸出後邊緣會浮白邊）
2. 先排好最終版面：後出現的元素不能把已經在畫面上的東西擠開；之後才會打勾的框，一開始就畫成空框佔位
3. 會放大的元素（聚焦、過衝）照放大後的大小預留位置，和旁邊元素的間距從放大後的邊量
4. 線與元件的距離、箭頭兩端：照「版面」第 7 條（連接線用 `data-links` 產生）
5. 同一欄（列）相鄰元件的間距：照「版面」第 2 條（用 `data-layout` 排）
6. 畫面上的字不用乘號「×」（字身小、浮在上面），改寫「倍」
7. 有底色或框的容器跟著內容一起進場，不要先放空底板等內容
8. 一幕 3–5 個重點，只往上加或局部變化；抖動、閃紅、脈衝這類動作一幕最多一次
9. 同一件事只說一次：裝置的狀態畫在它自己的螢幕或路徑上，不再加一行提示字；講解沒講的東西不加裝飾
10. 畫面上的字忠於講解，不自己編數字或引言
11. 示意介面先讓完整畫面停 0.8–1.5 秒，觀眾看清楚在哪裡，再推近或聚焦重點
12. 運鏡先數次數：一段裡慢推最多 2 次、每次至少 2 秒；不要先拉遠再推近
13. 假的密文、雜湊、token 照真實長度畫（一長串、結尾「…」），不要寫成短碼
14. 沒錄到的真實軟體畫面用 `x-ui-mock` 畫時，角落加「示意」小標

audit 會量、不用自己算的：標籤 ≤ 10 字、同一列元件中線對齊、不閃爍（亮滅超過 1 次）、元件進場完才描線；完成態、段尾停留、字幕區、子母畫面照舊由 audit 量。違反時照它印的改法改。

## 字卡文字

- 8–14 個字，是重點摘要，不是逐字照抄字幕（每個欄位的上限照 `build.mjs --spec` 印的，比這裡小就照它）
- 密度：每 1–4 句一段畫面變化（換段，或同一段裡的下一拍、下一條都算）；同一件事的幾句併成一段，不用為了 4 句拆開。整支片不留沒有畫面的空白；實機操作的段落可以只靠螢幕錄影的運鏡、紅框
- 開場 30 秒不限張數
- 字卡動態（fx）用在情緒、轉場、數字、口號句，不限張數，但不和下方字卡同時出現。40 張都標了「適合的語意」（`build.mjs --list` 最後一欄）：語意地圖的第二回合會照那一行的語意輪流列兩張候選，照它挑，不要每次都用同幾張；同一張一集最多 2 次（29 數字計數不算），第 3 次 build 會 ⚠
- 不下卡的情況
  - 操作指示句（例如「點擊右上角」）
  - 成功、完成之類的狀態句
  - 只有一句話的打勾項目（要湊成清單才下）
  - 很長的提示詞：去空白後 ≥ 50 字就不下卡，交給字幕＋錄影（≤ 49 字可以用情境動畫 `x-prompt`）；網址超過 34 個半形字同樣不下卡
- 「提醒」卡只寫提醒與注意事項
- 講到 3 個以上並列的項目，用條列（12／13）或側邊欄（03）、全畫面清單（04a）
- 文案傾向：
  - 具體實例優先：寫看得到的數字或結果，不寫抽象形容（例：「提升效率」→「3 小時變 20 分鐘」）
  - 動詞放前面：先講要做什麼（例：「字幕的校對」→「校對字幕」）
- 金句：先在分鏡表列「金句候選」讓作者勾，勾了才上；候選每集最多 6 則（建議初值）；分章寫草稿時每份最多 2 則，挑最像翻轉句的

## 螢幕錄影與圖片

插入的做法（plan.json 的 media 段、怎麼配對、座標怎麼讀）在 `shared/template/USAGE.md` 第 5 節；這裡是節奏與標註的規則。

- 只有聲音的旁白一定要配畫面（螢幕錄影或圖片；找不到對得上講解的素材就做全幕情境動畫），不留黑畫面
- 一段講解配一段錄影：從講到那個操作的那一則字幕開始，講完就回到講者；錄影要和講解講的是同一個操作，對不上就調起點、變速或拆段，不要讓觀眾看著別的畫面聽說明
- 錄影太慢可以加速（寫 `out` 讓 build 算速度，上限 4 倍）；有游標移動、打字的畫面不超過 1.5 倍。純等待（載入、AI 生成）用 `retime` 跳過：同一段裡寫「講到這裡錄影在第幾秒」，3 秒內可到 64 倍，運鏡和紅框不會斷；要點之前可以放慢（下限 0.25 倍）。一段有快有慢有停就用 `retime`，不要拆成好幾段
- 定格（`hold`，或 `retime` 裡 `src` 一樣的兩點）：講解停在一個結果畫面講好幾句、要對著畫面逐項說明，或錄影會閃過不該露的東西（指令）時，用定格停在那一格（1–13 秒；超過 15 秒改全幕情境動畫）；畫面露出金鑰、密碼、個資一定要 `redact` 打碼；箭頭、說明卡、放大鏡優先放在定格段。沒寫 `hold` 卻停住的錄影才是錯
- 段尾 0.5 秒不能露出下一步的畫面：`to` 提早，或那一段改 `hold`
- 錄影露出個資（資料夾名稱、email、金鑰、通知）：換一段沒有的、用 `hold` 停在乾淨的那格，都不行就告訴使用者，不要硬放
- 錄影預設靜音，只聽講解；講解在講錄影本身的聲音（提示音、語音回覆）時才保留（`volume` 先寫 −6，蓋過人聲再調小）
- 講者縮到右下角子母畫面；只有聲音的段落沒有講者，不放子母畫面，全畫面的段自動換「全寬」版型（本檔「版面」）
- 進出場（`enter`／`exit`）：不寫＝`"fade"`（從講者進來時面板從小視窗長出），大部分的段不用改。要換時一個情況一種寫法，錄影段都不配音效：
  - 講者一句話就切去看操作、操作講完馬上回講者（節奏快的地方）→ `"enter": "whip"`、`"exit": "whip"`（甩鏡 0.3 秒）；一支片只用在幾個節奏轉折，相鄰兩段 media 不要都甩
  - 第一次端出成品、結果畫面、產品圖（「做出來就是這樣」）→ `"enter": "tilt"`（斜躺擺平 0.65 秒；要 `fit` `"contain"`）
  - 一張參考圖貼在背景上（網頁截圖、文件一頁）→ `"enter": "tape"`（只給圖片、橫式）
- 橫式錄影段的子母畫面要在錄影範圍內：工具自動移進素材右下角，外框離素材邊 16（16:9 錄影：本體 x 1339–1771、y 591–915，右緣和小節角標對齊），不用寫座標；小視窗只碰到素材邊邊（手機直式、正方形的圖）才留在畫布右下；和位置不同的段相接時滑 0.6 秒過去
- 錄影段落不放下方資訊卡；要強調畫面上的東西，用紅框、說明卡、聚光燈、箭頭、運鏡、放大鏡；字卡密度往稀的那端下
- 說明卡（callout）屬於標註，不是資訊卡：它是紅框旁邊用引線接出去的一張小卡，只在錄影段用，所以不違反「錄影段落不放下方資訊卡」。一張卡只寫一個名詞或一個動作，最多 12 字（全形 1、半形 0.5），可以配一個圖示；細節交給講解
- 說明卡至少完整停 1.2 秒（一般進場 until − at ≥ 2.35 秒）；短句用 quick 一起淡入，至少完整停 0.8 秒（until − at ≥ 1.35 秒）；卡片放框的哪一邊由 build 自動挑，放不下會告訴你換哪邊
- 紅框：框整個控制項（輸入框連外框、清單列連左邊的圖示），元素在框裡置中；實線 4px、警示紅、硬邊無光暈，上下左右內距相等；同一時間最多 2 個（說明卡的框也算）；位置相近、連續講同一塊時一開始就畫一個大框，不要一句一框反覆閃；停不到 0.5 秒的不畫；最後一個框講完再多停 1 秒
- 錄影在捲動、要框的東西跟著移動時，讓同一個紅框跟著移（path），不要拿掉再畫一個新框；換目標 0.4 秒、跟捲動用錄影捲動的秒數
- 聚光燈（spot）：其他地方壓暗 35%，只留要看的那一塊；一次一個、至少 2 秒，不和放大鏡同時
- 直式／窄的錄影（手機畫面，寬 < 高）在橫式影片：寫 `side`（右側步驟清單）—— 錄影靠左（左邊 720 寬）、右邊一張卡＝標題（≤ 12 字）＋1–5 條步驟（每條 ≤ 14 字），一開始淡淡列著，講到那條（`at` 綁 `#N@詞`）亮起、講過的變淡；有講者小視窗時卡在小視窗上方、最多 2 條；沒寫 `side` 時 `--check` ⚠（兩邊空著）
- STEP 膠囊（steps）：多步驟的操作才用，掛在錄影可見區的左上角（離錄影邊 32 px；壓到紅框時 build 自動換右上）；每一步最多 12 字，相鄰兩步至少隔 1.65 秒；號碼全片接著數，同一個步驟在下一段繼續講時寫一樣的字，號碼沿用、膠囊不重播；錄影檔名或講稿寫了「STEP N｜…」就照那個步驟名
- 箭頭（arrows）：給小按鈕、小圖示這種紅框框不清楚的地方；箭尖離目標 6–12 px（build 用 9 px），不壓到字、卡片、膠囊與紅框線；找不到不擋字的位置就不放（build 會自動拿掉並提醒）；一次一支、至少 2.2 秒；放大鏡期間不放
- 點擊前先指路：講解說「點／按 X」而且畫面真的按下時，`clicks` 配點擊音效，再加一支箭頭先指到 X（`at`＝講到 X，`until`＝按下前 0.3 秒）；按下那一格落在講解動詞前後 0.3 秒內，對不上就調 `in`
- 說明卡、聚光燈、箭頭出現的期間畫面不能動：運鏡要在標註之前結束，或等標註退場後再動；有這三種標註的圖片不做慢推
- 運鏡：推近到講解在講的那一塊，講完拉回全景；推近、拉回至少 1.5 秒（倍率 ≥ 2 時至少 2.2 秒，不寫 `dur` 就是這個）；一段最多 2 次；第一次至少在段起點 0.8 秒後（先看全景）；不先拉遠再推近；兩個框倍率差超過 1.4 倍時先拉回全景或拆段硬切；推近不超過 4 倍（再大會糊，改用放大鏡）。違反時 build 會 ⚠（參考專案作者：「跳來跳去，眼睛受不了」）
- 放大鏡：給小字、數字、小按鈕；講解唸出畫面上的字（版號、路徑、網址、數字、按鈕名）那句用放大鏡或推近，沒唸字就不用；只框要看清的那一小塊，等比放大；至少停 1.2 秒；一次一個，不和運鏡同時
- 標註不要密：一段錄影平均 4 秒最多一個標註（紅框、說明卡、箭頭、放大鏡合計），說明卡一段最多 2 張
- 標註也不能沒有：講解講到畫面上的東西（按鈕、欄位、選項、數字，或說「這邊」「點」「選」）那句一定要標；≥ 4 秒的錄影段一個標註、運鏡都沒有，`--check` 會 ⚠
- 圖片沒有標註時預設整段緩慢推近（1.00→1.05），讓畫面不要死板

## 音效

只能用 `shared/sfx/` 裡的檔案。`ding`、`success`、`alert`、`impact` 各有兩個升降半音的變體（`ding-2.wav` 這類），build 照出現順序自動輪著放；plan.json 和分鏡表一律只寫本尊的名稱，不要寫變體的檔名。**音效照講者的情緒放，不照選了哪個模板**（2026-11-09 作者）：寫分鏡草稿時標情緒點（plan.json 第一層 `moods`），停點 ③ 分鏡表的「情緒點」勾選表和頁首的情緒曲線給作者定。模板的預設音效（「模板預設音效」那張表）只在那一分鐘沒有情緒點時才補，分鏡表每段的音效欄寫「預設」就好；只有要換、要拿掉、要加點擊、要配結尾配樂，才在段上寫。

### 情緒點（moods）

| `kind` | 情緒 | 什麼時候標 | 音效 |
|---|---|---|---|
| `pain` | 痛點 | 踩坑、錯誤、壓力、「千萬不要」 | `alert`（更重的寫 `"sfx": "thunder"`） |
| `win` | 解法 | 問題解決、成果、「終於」「搞定」 | `success` |
| `turn` | 反轉 | 「竟然」「沒想到」，預期被推翻 | `shine` |
| `land` | 落定 | 數字、結論落地那一下 | `impact` |
| `quote` | 金句 | 整集最想讓人記住的一句 | `sparkle` |

- 寫法：`{ "at": "#N@詞", "kind": "pain" }`。`#N@詞` 寫講者情緒最強的那個詞（字幕裡連續的字），音效的峰值對齊那個詞開口
- 約每分鐘 1 個。同一分鐘最多 2 顆主音效、相距至少 3 秒，超過時工具照強弱留（金句、反轉 > 痛點、解法 > 落定 > 模板預設），不用自己算
- `"sfx": null`＝這個點不要音效（只留推近）；`"sfx": "<名稱>"`＝換別顆
- `"zoom": true`＝講者畫面爆衝推近（0.2 秒推到 1.25 倍，停到這句講完，下一句切回）：只給金句、反轉、數字落定這種最強的一下，約每分鐘最多 1 次；那一刻講者被整張幕、側邊欄蓋住，工具自動拿掉
- 段上明寫的 `sfx`、章節音效最優先；剪輯台改過的照剪輯台
- 每集上限照下表（`shine` 3、`sparkle` 6、`thunder` 3 次）：情緒點超過的，工具從後面的開始換成 `ding`（`thunder` 換 `alert`）

### 模板預設音效（那一分鐘沒有情緒點時才補）

字卡揭開、條列逐條、側邊欄推入、全畫面幕進場、切到螢幕錄影、翻牌、打字、故障、鋪墊上升都**不配音效**（2026-11-02 作者：音效只留下表這幾顆）。

| 事件 | 音效 | 峰值對齊哪一格 | 預設配給哪些情境 | 每集上限 |
|---|---|---|---|---|
| 章節轉場 | `chapter.wav` | 章名落定那一格 | 01 | — |
| 講重點、提醒、答案揭曉 | `ding.wav` | 重點字出現那一格 | 07、09 答案（附加） | — |
| 解法、成果、問題解決 | `success.wav` | 綠勾或結果出現那一格 | 07 `tone: "good"`；情境動畫的結果那拍（分鏡「音效拍點」寫） | — |
| 踩坑、錯誤、限制 | `alert.wav` | 紅章或警告出現那一格 | 07 `tone: "warn"`；情境動畫的壞事那拍（分鏡「音效拍點」寫） | — |
| 錄影或動畫裡的游標點擊（附加） | `click.wav` | 游標按下那一格 | 段落寫 `clicks` 才有 | — |
| 入場、介紹主角、金句閃亮 | `sparkle.wav` | 主角或金句出現完成那一格 | 14、15 | 6 次 |
| 轉折亮點：本集最得意的設計、關鍵詞大字 | `shine.wav` | 關鍵詞到位那一格 | 沒有預設，那段寫 `"sfx": "shine"` | 3 次 |
| 負面：壓力、焦慮、晴天霹靂 | `thunder.wav` | 負面問句或壞消息出現那一格 | 15 `tone: "warn"` | 3 次 |
| 蓋章、重擊、數字或金句落定 | `impact.wav` | 落地那一格 | 字卡動態 | — |
| 結尾配樂 | `bgm-cylinder-five.wav` | 結語金句講完後那一句的起點 | 預設不配；plan.json 第一層的 `"outro"` 寫 `"music": "bgm-cylinder-five"` 才有（一集一首） | — |

- 一張卡最多一個主音效
- 兩個主音效相距不到 3 秒時，只留比較重要的（段上明寫 > 情緒點 > 模板預設；同一級留前一個）；附加音效（`click`、QA 答案的 `ding`）不算
- 超過 60 秒沒有主音效時 build 會提醒（音效稀疏）：有情緒點的專案，在空檔裡挑情緒最強的一句加一個情緒點（或在分鏡表的「情緒點」勾回來）；沒有情緒點的舊專案，每個空檔都要補，括號裡列出那段時間的情境動畫和錄影段，在那一段找踩坑句配 `alert`、解法或結果句配 `success`（一組問題→解法前後呼應），落在句尾前 0.1–0.2 秒；情境動畫在那一拍寫 `P.sfx('success', '#12@詞')`，錄影段、字卡段寫 `"sfx": { "name": "success", "at": "#12e-0.1" }`（2026-11-03 作者：一整段沒有音效聽起來是空的）
- 補稀疏和每分鐘上限一起看：在空檔裡挑離前後主音效都最遠的那一拍補（例：空檔 0:40–2:10，補在 1:20 附近）；那一分鐘已經 2 顆就往空檔中間挪到下一分鐘
- 每分鐘最多 2 顆主音效（附加音效不算）；超過時 build 自動拿掉，留最重要的：段上明寫的、情緒點（照強弱）先留，模板預設裡 `chapter`、`thunder`、`shine`、`sparkle`、`alert`、`success` 先留，`ding`、`impact` 先拿掉。段上明寫的 `sfx` 不會被拿掉，那樣還是超過才 ⚠（那段寫 `"sfx": null`）
- 音效大小已調好（`kit/sfx.json` 的 `volume`），每一顆都要比人聲小至少 3 dB；build 報告的「音效比例」會列出超過的
- 錄影或模板動畫段裡**看得到游標按下**的地方，在那段寫 `"clicks": ["+秒數" 或 "#N@詞", …]`，一下一顆；講解說「按下去」但畫面沒有點擊，不寫。內容設計動畫的點擊寫在動畫檔的 `P.sfx('click', '#N@詞')`，不寫 clicks
- 結尾配樂：預設不配，但每集都要問（build 沒寫 outro 時印「結尾配樂：沒配…」，停點回報照貼）。要配就在 plan.json 第一層寫 `"outro": { "from": "#N", "music": "bgm-cylinder-five" }`（N＝結語金句講完後那一句），配樂淡入、墊在講話底下、播到片尾
- `bgm-cylinder-five` 是 Chris Zabriskie〈Cylinder Five〉，CC BY 4.0：用到的影片要在說明欄貼 build 印的出處那一行（`kit/sfx.json` 的 `credit`）
- 底樂（選用，預設沒有）：整支片墊一首配樂。講話時比人聲小 20 dB，沒人講話的空檔最多回升 6 dB；片頭淡入 2 秒，片尾淡出 3 秒；曲子比影片短就循環，接點交叉淡化 3 秒；有片尾配樂時，底樂在片尾配樂起播的地方淡出，兩首不疊。曲子至少 20 秒才能當底樂。曲庫的檔一律調到 −20 LUFS。只能用曲庫的曲子（`shared/music/`、這一集的 `work/music/`），由 `music.mjs` 放進去
- 個別音效太大聲或太小聲，在剪輯台調那一段的音量（plan.json 的 `sfxVolume`，dB）；全部一起調用剪輯台的「音效」（`edit.volume.sfx`，結尾配樂也跟著）

## 審查門檻

抽查截圖、看觀影總表時用（量法與回報格式在 `shared/template/REVIEW.md`）。數字只寫在這裡，REVIEW.md 引用。

| 類別 | 算問題的條件 |
|---|---|
| 閃動 | 元素出現不到 0.3 秒就消失；畫面只剩背景超過 0.3 秒 |
| 講者閃一下 | 兩段之間只空不到 1.0 秒，講者露一下又被蓋住 |
| 同步 | 卡片、標註比講解講到的那一刻早或晚超過 0.5 秒 |
| 停留 | 新訊息完成態不到 1.2 秒；段尾最後一幕不到 1.5 秒（「節奏」的完成態停留） |
| 音效 | 兩個主音效相距不到 3 秒；章節轉場前後 2 秒內又有別的主音效；某一分鐘主音效超過 2 顆；`sparkle`、`shine`、`thunder` 超過每集上限 |
| 靜止 | 畫面 ≥ 8 秒幾乎不變（觀影總表的靜止區間），而且講解在講新東西 |
| 沒有畫面 | build `--check` 的「沒有畫面的區間」不是「無」；只有聲音的區間沒被蓋住（build 印 ⚠ 或 ✖） |
| 字幕 | 一則超過 18 字、排成兩行、斷在詞中間、錯字、對不上嘴 |
